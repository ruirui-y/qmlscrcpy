# 剪贴板同步

电脑和手机之间互传文字。工具栏两个按钮：

```
[发给手机]  把电脑剪贴板里的文字写进手机剪贴板，并自动粘贴到当前输入框
[取回电脑]  读取手机剪贴板，写进电脑剪贴板
```

## 1. 协议怎么走

scrcpy 的控制 socket 是**双向**的，之前我们只写不读，所以只能发不能收：

```
                    ┌──────────── 控制 socket ────────────┐
电脑                                        手机
SET_CLIPBOARD (9)   ── 序号 + paste + 长度 + UTF-8 ──▶  写剪贴板，paste=1 就顺手粘贴
                                                          │
                          ┌── Clipboard (0) 消息 ◀────────┘
GET_CLIPBOARD (8)   ── copy/cut ──▶                      读剪贴板，把内容推回来
```

| 消息 | 类型号 | 负载 |
|---|---|---|
| `SET_CLIPBOARD` | 9 | `序号 u64 + paste u8 + 长度 u32 + UTF-8 文本` |
| `GET_CLIPBOARD` | 8 | `copy/cut u8` |
| `CLIPBOARD`（设备→电脑） | 0 | `长度 u32 + UTF-8 文本` |
| `ACK_CLIPBOARD`（设备→电脑） | 1 | `序号 u64` |

## 2. 为什么之前收不到设备消息

`DeviceController::SendControl()` 只往 socket 写；`server_session` 里的 `control_socket_` 一直没人读。现在：

```cpp
control_reader_ = session_->ControlSocket();
QObject::connect(control_reader_, &QTcpSocket::readyRead, this, &DeviceController::OnControlData);
```

`OnControlData()` 按协议切消息（`DeviceMessage::TryParse` 返回消费字节数，0 表示半条，等下一次数据），拿到 `Clipboard` 就写电脑剪贴板。

**TCP 是字节流**，所以必须自己攒缓冲：一包可能只有半条消息，也可能连着好几条。

## 3. 类型号踩坑：单测自比查不出错

设备消息的类型号必须和 scrcpy 服务端的 `DeviceMessage.java` 一致：

```java
public static final int TYPE_CLIPBOARD = 0;
public static final int TYPE_ACK_CLIPBOARD = 1;
```

我们最初写成 `1 / 2 / 3`，结果「发给手机」能work（单向写，不需要读），「取回电脑」永远收不到。

**为什么单测没发现**：测试里写的是 `static_cast<quint8>(DeviceMessage::Type::Clipboard)`，自己和自己比，枚举值错了也照样通过。现在补了一条锁死的用例：

```cpp
QCOMPARE(static_cast<quint8>(DeviceMessage::Type::Clipboard), quint8(0));
```

教训：**凡是"我们自己编码、对面解码"的数字，单测必须对着协议常量断言，不能对着自己的枚举断言**。

## 4. 为什么不用 Ctrl+C 自动发

想过做成"电脑一 Ctrl+C 就自动推到手机"，最后没做，原因有两个：

1. **Ctrl+C/V 在投屏里的含义是冲突的**：焦点在手机画面上时，`Ctrl+C` 到底是电脑复制、还是把手机里的内容复制？用户没法预期
2. **自动推送会把敏感内容送出去**：密码管理器、聊天记录，只要复制过就同步到手机，卸载重装也追不回来

所以默认就是**显式两个按钮**，按一次做一次。想要自动同步的人可以在 `config.ini` 里开 `input/clipboard_autosync=true`（只做"电脑→手机"方向，且接收手机内容时会抑制回环）。

## 5. 自动同步（默认关）

`config.ini`：

```ini
[input]
# 电脑剪贴板一变就自动推到设备（会同步敏感内容，默认关）
clipboard_autosync=false
```

打开后监视 `QClipboard::dataChanged`，一变就把内容发过去。

**这里有个回环坑**：我们写电脑剪贴板（接收手机内容）时也会触发 `dataChanged`，如果不拦住，就会出现"手机→电脑→手机"来回推。所以用一个开关：

```cpp
suppress_clipboard_ = true;
QGuiApplication::clipboard()->setText(message.text_);
suppress_clipboard_ = false;
```

`OnLocalClipboardChanged()` 里先看这个标志。

## 6. 怎么用

**电脑 → 手机**（比如把网页链接发到手机微信）：

```
① 电脑上 Ctrl+C 复制
② 投屏窗工具栏点「发给手机」
③ 手机上当前输入框直接出现这段文字（paste=1 自动粘贴）
④ 按发送
```

**手机 → 电脑**（比如把手机上的验证码贴到电脑）：

```
① 手机上复制
② 点「取回电脑」
③ 电脑上 Ctrl+V
```

## 7. 已知限制

- 只支持**纯文本**，图片/文件不同步
- 单次内容上限约 250 KB（协议里 `kMaxClipboardBytes`）
- 手机端要 Android 7 以上（scrcpy 的服务端依赖），旧设备可能不响应 `GET_CLIPBOARD`
- 中文没问题——这条路径传的是 UTF-8 文本，不是按键码，所以**中文输入法解决不了的事，剪贴板可以**（手机上贴进去即可）
