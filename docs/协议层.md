# 协议层

对齐 scrcpy 3.3.3（`third_party/scrcpy-server` 固定这个版本）。只实现单向用的那几类消息。

## 视频包

每个包 = 12 字节头 + 负载：

```
字节 0                              7 8                 11
┌────────────────────────────────────┬───────────────────┐
│ 标志位 + 时间戳（64 位，大端）        │ 负载长度（32 位）  │
└────────────────────────────────────┴───────────────────┘
  bit63 = 配置包（SPS/PPS）
  bit62 = 关键帧
  bit0..61 = 展示时间戳（微秒）
```

代码：`libs/protocol/video_packet.h` / `.cpp`，`VideoPacketHeader::Parse` 只读不消费。

配置包不产生画面，作用是把 SPS/PPS 送给解码器；解码器要求"参数集 + 第一个关键帧"一起喂，所以 `H264Decoder::Push` 会把配置包存起来、拼到下一个普通帧前面。

## 控制消息（主机 → 设备）

```
┌──────────┬──────────┬───────────────────────┐
│ type (1) │ len (4)  │ 负载（len 字节）        │
└──────────┴──────────┴───────────────────────┘
```

已实现的 12 种（`control_message.h` 的 `ControlType`）：

| 值 | 名称 | 负载 |
|---|---|---|
| 0 | InjectKeycode | action + keycode + repeat + metaState |
| 1 | InjectText | 文本 UTF-8（≤300 字节） |
| 2 | InjectTouch | action + pointerId + 位置 + 屏幕尺寸 + 压力 + 按键 |
| 3 | InjectScroll | 位置 + 屏幕尺寸 + 水平 + 垂直 + 按键 |
| 4 | BackOrScreenOn | action |
| 5 | ExpandNotificationPanel | 无 |
| 6 | ExpandSettingsPanel | 无 |
| 7 | CollapsePanels | 无 |
| 8 | GetClipboard | copyKey |
| 9 | SetClipboard | 序号 + paste + 文本 |
| 10 | SetScreenPowerMode | 模式 |
| 11 | RotateDevice | 无 |

### 触摸消息的坐标约定（重要）

位置是**视频帧坐标系里的像素** + 视频帧尺寸，不是 0..1 归一化：

```
x (4) │ y (4) │ 视频宽 (2) │ 视频高 (2)
```

设备端拿到 `sc_position` 后靠 `screen_size` 换算到真实屏幕。送归一化值会点偏，这是后加的输入层（`libs/input`）必须先做坐标映射的原因。

压力是 16 位定点（0..65535），按下给满值 `0xFFFF`。

## 设备消息（设备 → 主机）

```
┌──────────┬───────────────────────┐
│ type (1) │ 负载                  │
└──────────┴───────────────────────┘
```

| 值 | 名称 | 负载 |
|---|---|---|
| 1 | Clipboard | 文本（UTF-8） |
| 2 | AckClipboard | 序号 |
| 3 | UhidOutput | 虚拟键鼠输出，明确不支持 |

`DeviceMessage::TryParse` 返回三态：正数 = 消费的字节数，0 = 数据还不够，-1 = 流坏了。这样调用方可以把它塞进循环里处理半包。

## 编码细节

- 全部**大端**（`wire.h` 的 `AppendU16/32/64`）
- 单条消息上限 256 KB（`kMaxMessageBytes`），超过就断开
- 文本类消息按 UTF-8 字符边界截断，不会把汉字切一半
