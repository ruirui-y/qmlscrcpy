# 窗口几何记忆

三扇窗各自记自己的位置尺寸，全在 `window.ini`。程序只写不读注释，所以不用担心 `QSettings` 把注释转义（`config.ini` 才是人改的那份）。

## 两扇窗是什么关系

```
控制窗（主）                投屏窗
   │                          │
   │ 完全独立                  │ 独立，内含画面 + 工具栏
   │ 关闭 = 退出进程            │ 关闭 = 只关画面（主窗还在）
```

```
┌──────────────────────────┐   ┌────────────────────────┬──────┐
│ QmlScrcpy                │   │ 标题栏（设备名/fps/提示） │ 工具栏│
│ [串号] [▾] [刷新][连接][断开]│   ├────────────────────────┼──────┤
│ ● 已连接 …                │   │       VideoSurface      │ 按钮列│
└──────────────────────────┘   └────────────────────────┴──────┘
```

三处关键行为：

- **启动只显示主窗**：投屏窗 `visible: false`，等 `connectedChanged` 变 true 才亮出来；断开连接自动收起
- **关掉投屏窗 = 断开连接**：✕ 和 Alt+F4 都会先 `Disconnect()` 再藏窗口。只藏窗口的话主窗还显示"已连接"，再点「连接」也不会把窗口叫回来，用户必须先点「断开」——这就是之前那个"窗口关了还显示连着"的 bug


- **投屏窗不再挂 owner**：`Component.onCompleted` 里写 `transientParent = null`。QML 窗口声明在另一窗口内部时会继承 `transientParent`，而 Win32 的规则是 owner 最小化时 owned 窗口一起隐藏——所以不加这句，主窗一最小化投屏窗就消失了
- **主窗关闭 = 进程退出**：`onClosing: Qt.quit()`。投屏窗、工具栏（现在在投屏窗里）跟着一起走

原来还有第三扇"工具栏窗口"，已经并进投屏窗，理由写在 [工具栏](工具栏.md)。
## 记什么

```ini
[video_pos]
x=247
y=121

[video_window]
x=247
y=121
w=414
h=938

[video_window_landscape]
x=380
y=260
w=900
h=430

[control_window]
x=742
y=361
w=600
h=250
```

| 键 | 谁的 | 说明 |
|---|---|---|
| `video_pos` | 投屏窗 | 竖屏位置 |
| `video_pos_landscape` | 投屏窗 | 横屏位置（和竖屏分开，互不影响） |
| `video_window` | 投屏窗 | 竖屏尺寸 |
| `video_window_landscape` | 投屏窗 | 横屏尺寸 |
| `control_window` | 控制窗 | 位置 + 尺寸 |

## 位置也分两套

一开始位置只记一个 `video_pos`，结果退出横屏时窗口是"以左上角为锚点"重排的，跑到屏幕左上角去了。现在位置也按姿势分开：

```qml
function positionKey() {
    return landscape ? "video_pos_landscape" : "video_pos"
}
```

切姿势时先存旧的、再取新的：

```qml
appSettings.SaveVideoGeometry(geometryKey(), x, y, width, height)
appSettings.SaveVideoPosition(positionKey(), x, y)      // 存到旧姿势
landscape = nowLandscape
const saved_position = appSettings.VideoPosition(positionKey())   // 取新姿势
if (saved_position.x >= 0 && saved_position.y >= 0) { x = ...; y = ... }
```

## 横屏第一版给多大

```qml
// 横屏没有历史记录时的默认值
width = Math.min(900, Screen.desktopAvailableWidth * 0.9)
height = Math.min(400 + titleBar.height, Screen.desktopAvailableHeight * 0.9)
```

900×400（画面区，窗口总高再加 30px 标题栏）是"能看清又不占满屏幕"的折中。之前按帧比例算出来接近全屏，太大；先试过 1300×600 仍然偏大。

## 老用户看不到新默认值：一次性迁移

改了默认值之后老用户还是看到大窗口，因为 `window.ini` 里存着按旧算法算出来的尺寸。光改代码没用，得把旧记录清一次：

```cpp
if (!window_store.contains(QStringLiteral("ui/landscape_default_v2")))
{
    window_store.remove(QStringLiteral("video_window_landscape"));
    window_store.remove(QStringLiteral("video_pos_landscape"));
    window_store.setValue(QStringLiteral("ui/landscape_default_v2"), true);
    window_store.sync();
}
```

用一个版本标记 `ui/landscape_default_v2` 保证**只清一次**：清完打上标记，之后用户自己调过的大小不会再被抹掉。

## 改了默认值为什么看不到变化

默认值只在**没有历史记录**时生效。`window.ini` 里已经有 `[video_window_landscape]` 的话，启动时会直接恢复旧尺寸，代码里的默认值根本走不到。

工具栏最下面有个「复位」按钮，点一下就等于把当前姿势的记录删掉并立刻套默认值，不用手改 ini。

它做的两件事：

```cpp
appSettings.ResetVideoGeometry(geometryKey())    // 删掉 [video_window] 或 [video_window_landscape]
videoWindow.resetToDefault()                     // 横屏 900x400；竖屏按帧比例重算
```

手工改也可以，删掉 `config/window.ini` 里这两段再启动：

```ini
[video_window_landscape]
[video_pos_landscape]
```

## 为什么横屏和竖屏各记一套

用户对两种姿势的窗口大小要求不一样：

```
竖屏刷手机：窄高，一屏看聊天列表    414 x 938
横屏看电影：宽扁，像个小电视        900 x 430
```

共用一套的后果：横屏时按竖屏尺寸显示 → 画面缩在中间一条缝；把窗口拉宽之后切回竖屏，又变成一根高瘦的条。所以按姿势分开记。

判定方式很朴素：`frameSize.width > frameSize.height` 就是横屏。帧尺寸变化时：

```
新增的横屏/竖屏 → 先把当前尺寸存进旧的那套 → 再取新姿势记住的尺寸
                   （没有记录就按帧比例自动算一套）
没变 → 什么都不做（避免每帧抖动去改窗口）
```

## 防抖：停手 400ms 才写盘

`onXChanged` / `onWidthChanged` 这些回调在拖动时会一秒触发上百次。第一版每次都 `QSettings::sync()` 落盘，**UI 直接卡住好几秒**。

现在统一走一个 400ms 的单次定时器：每次变化只是 `restart()`，停手之后才真正写一次。

## 程序自己改的尺寸也要记

自动按帧比例算出来的尺寸，缩放手势没触发过，用户也就"没改过"。但下次启动还是要用它，所以在算完之后主动 `saveTimer.restart()` 一次，把算出来的几何当成用户的选择存下来。

## 右下角缩放把手

一开始是三根 1px 的浅灰斜线，几乎看不见。现在是深色底块 18×18 + 三根 2px 亮灰斜线（`#b8b8b8`），鼠标悬停还会变成斜向双箭头光标。

位置也有讲究：**把手放在"画面 + 把手"那个 Item 里**，贴它的右下角，而不是贴整个窗口。

```qml
Item {                                   // 视频区
    Layout.fillWidth: true
    Layout.fillHeight: true
    VideoSurface { anchors.fill: parent }
    Rectangle { anchors.right: parent.right; anchors.bottom: parent.bottom }   // 把手
}
```

早期版本把手是窗口的兄弟节点，靠 `toolBar.left` 反推位置，布局还没算完时 `toolBar.left` 是 0，把手就跑到窗口最左边去了。放进视频区之后坐标只依赖画面本身，跟工具栏在不在、是否全屏都无关。

## 换屏的兜底

`onScreenChanged` 里保证窗口不小于最小尺寸：

```qml
onScreenChanged: {
    width = Math.max(width, minimumWidth)
    height = Math.max(height, minimumHeight)
}
```

控制窗默认 600×250（最小同值）是按内容算的：宽度 = 输入框最少 140 + 菜单 28 + 三个按钮 72×3 + 间距 + 边距（小于它内容会被裁掉，这就是之前在另一块屏上"按钮只剩半截"的原因）。高度保持 250：画质面板已经压紧到 164px，靠上摆放不会被裁（细节见 [主窗口](主窗口.md)）。

## 位置恢复的边界

- 保存的 `x/y` 是 **-1** 或窗口尺寸 ≤ 0 时（没记录）不恢复，交给 Qt 默认摆放，然后立刻把默认位置存一次，保证下次还在那儿
- 屏幕拔掉 / 分辨率变化导致保存的位置在屏幕外时，Qt 会把窗口挪回可见区域，不是我们的责任，但也不会崩
