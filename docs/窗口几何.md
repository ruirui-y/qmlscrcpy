# 窗口几何记忆

三扇窗各自记自己的位置尺寸，全在 `window.ini`。程序只写不读注释，所以不用担心 `QSettings` 把注释转义（`config.ini` 才是人改的那份）。

## 记什么

```ini
[video_pos]
x=247
y=121

[video_window]
x=247
y=121
w=414
h=938

[video_window_landscape]
x=380
y=260
w=900
h=430

[control_window]
x=742
y=361
w=600
h=250
```

| 键 | 谁的 | 说明 |
|---|---|---|
| `video_pos` | 投屏窗 | 只记位置，横竖屏共用 |
| `video_window` | 投屏窗 | 竖屏尺寸 |
| `video_window_landscape` | 投屏窗 | 横屏尺寸 |
| `control_window` | 控制窗 | 位置 + 尺寸 |

## 为什么横屏和竖屏各记一套

用户对两种姿势的窗口大小要求不一样：

```
竖屏刷手机：窄高，一屏看聊天列表    414 x 938
横屏看电影：宽扁，像个小电视        900 x 430
```

共用一套的后果：横屏时按竖屏尺寸显示 → 画面缩在中间一条缝；把窗口拉宽之后切回竖屏，又变成一根高瘦的条。所以按姿势分开记。

判定方式很朴素：`frameSize.width > frameSize.height` 就是横屏。帧尺寸变化时：

```
新增的横屏/竖屏 → 先把当前尺寸存进旧的那套 → 再取新姿势记住的尺寸
                   （没有记录就按帧比例自动算一套）
没变 → 什么都不做（避免每帧抖动去改窗口）
```

## 防抖：停手 400ms 才写盘

`onXChanged` / `onWidthChanged` 这些回调在拖动时会一秒触发上百次。第一版每次都 `QSettings::sync()` 落盘，**UI 直接卡住好几秒**。

现在统一走一个 400ms 的单次定时器：每次变化只是 `restart()`，停手之后才真正写一次。

## 程序自己改的尺寸也要记

自动按帧比例算出来的尺寸，缩放手势没触发过，用户也就"没改过"。但下次启动还是要用它，所以在算完之后主动 `saveTimer.restart()` 一次，把算出来的几何当成用户的选择存下来。

## 右下角缩放把手

一开始是三根 1px 的浅灰斜线，几乎看不见。现在是深色底块 18×18 + 三根 2px 亮灰斜线（`#b8b8b8`），鼠标悬停还会变成斜向双箭头光标。

## 换屏的兜底

`onScreenChanged` 里保证窗口不小于最小尺寸：

```qml
onScreenChanged: {
    width = Math.max(width, minimumWidth)
    height = Math.max(height, minimumHeight)
}
```

控制窗最小 600×250 是按内容算的：输入框最少 140 + 菜单 28 + 三个按钮 72×3 + 间距 + 卡片边距。小于这个宽度内容会被裁掉——这正是之前在另一块屏上"按钮只剩半截"的原因。

## 位置恢复的边界

- 保存的 `x/y` 是 **-1** 或窗口尺寸 ≤ 0 时（没记录）不恢复，交给 Qt 默认摆放，然后立刻把默认位置存一次，保证下次还在那儿
- 屏幕拔掉 / 分辨率变化导致保存的位置在屏幕外时，Qt 会把窗口挪回可见区域，不是我们的责任，但也不会崩
