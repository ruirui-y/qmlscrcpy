# 渲染方案

结论先给：**用 `QQuickFramebufferObject`，在 `Renderer::render()` 里画**。这是 Qt5 里唯一"GL 上下文保证当前"的自定义渲染入口。

## 三条路

| 方案 | 做法 | 代价 | 谁在用 |
|---|---|---|---|
| A 自己开窗口 | 拿 HWND 建交换链，直接 Present | 窗口/事件/DPI/输入全自己写 | scrcpy（SDL）、Player 项目（D3D11） |
| B Qt Quick + FBO | `render()` 里画进 FBO，Qt 合成 | 多一次 GPU blit + 一次平面拷贝 | 本项目 |
| C Qt Quick + 自定义材质 | 往场景图里塞纹理和材质 | 省掉 FBO blit，但 GL 时机不受控 | 试过，崩了五次 |

## 为什么不是 A

A 是最直接的：一个窗口句柄 + 一个交换链 + 两个着色器就够了。Player 项目就是这么干的（`D3D11Pipeline::Execute` → `Draw(3,0)` → `Present`），全程在一个线程里，没有 FBO，没有合成器。

但我们用的是 Qt Quick：窗口、GL 上下文、事件循环都归它。要在它管理的窗口上再挂一个自己的交换链，等于两套合成打架。走 A 就得把投屏窗从 QML 降级成原生窗口，窗口管理、拖拽、DPI、输入全部自己重写。

**现在多花的成本约 1 ms/帧，换来的是窗口管理白拿。** 60fps 预算 16.7ms，解码已占 5.6ms，这 1ms 不值得省。

## 为什么不是 C（踩坑记录）

自定义 `QSGNode` + 材质理论上最快，但 Qt 对"在场景图里自己播 GL"的容忍度极低：

| 尝试 | 结果 |
|---|---|
| `QSGSimpleTextureNode` 每帧换纹理 | 崩：材质被渲染器缓存，纹理被自己删了，`bind()` 野指针 |
| 材质持有 AVFrame 跨帧 | 崩：断开连接时帧活过解码器，`shared_ptr` 析构 use-after-free |
| 在 `updatePaintNode` 里 `glTexSubImage2D` | 崩：那里的上下文状态不保证 |
| 自管 GLuint + `updateTexture` 上传 | 绿屏 + 崩 |

共同点：**GL 调用的时机不对**。`updatePaintNode` 是"同步阶段"，不是渲染阶段。

## B 的正确姿势

```cpp
class VideoItem : public QQuickFramebufferObject
{
    Renderer *createRenderer() const override;   // 返回自己的 Renderer
};

class YuvRenderer : public QQuickFramebufferObject::Renderer
{
    void synchronize(QQuickFramebufferObject *item) override;   // 渲染线程，无 GL
    void render() override;                                     // 渲染线程，GL 当前
};
```

两个回调的分工：

- `synchronize()`：把 GUI/视频线程那边的数据搬过来（拷三平面），**不能调 GL**
- `render()`：建纹理、上传、画——**所有 GL 都在这儿**

另外两条硬性要求：

```cpp
// ① 用完要把 GL 状态还回去，否则 Qt 接着画自己的东西时会出错
glActiveTexture(GL_TEXTURE0);
glPixelStorei(GL_UNPACK_ALIGNMENT, 4);

// ② v 轴要反向：FBO 的 y 朝上
//    顶点用 v=1 放顶部，否则整幅画面上下颠倒
```

这两条都踩过：状态没还原导致标题栏文字糊成一团，v 轴没反向导致画面上下颠倒。

## 三平面着色器

```
纹理 0：Y 平面（GL_LUMINANCE，全尺寸）      采样 .r
纹理 1：U 平面（半尺寸）                     采样 .r
纹理 2：V 平面（半尺寸）                     采样 .r
        │
        ▼
BT.601 有限范围矩阵（Android 屏幕采集默认）：
    y -= 0.0625     u -= 0.5     v -= 0.5
    R = 1.164y + 1.596v
    G = 1.164y - 0.391u - 0.813v
    B = 1.164y + 2.018u
```

如果颜色偏（发灰/发绿），先换 BT.709 再排查。

## 缩放与清晰度

窗口尺寸决定清晰度：

```
窗口比帧小 → 缩小，清晰（只是有点软）
窗口比帧大 → 放大，糊
```

所以首次连上时按帧的物理像素定窗口大小（`frameSize / devicePixelRatio`），再用屏幕可用区域封顶。用户手动调过之后记进 `userdata.ini`，下次照原样恢复。

采集分辨率用原生（`max_size=0`，1264×2776）。之前用 720（328×720）拉到全屏窗口，插值放大，字全是糊的。
