# 视频链路

从 socket 里的一串字节，到屏幕上的一帧画面。

## 全链路

```
设备 MediaCodec
    │
    ▼
┌────────────────────── 视频线程 VideoReader ──────────────────────┐
│ ① waitForReadyRead(200)         等数据（实测 6.0 ms/帧）          │
│ ② readAll → buffer append       收包，多出来的留给下一轮           │
│ ③ 解 12 字节头 → 拼满整帧        帧边界自己数，TCP 没有消息边界      │
│ ④ buffer.mid(12, len)           切出负载                         │
│ ⑤ buffer.remove(0, 12+len)      消费掉这一帧，否则下一轮重复解      │
│ ⑥ H264Decoder::Push             解码（实测 5.6 ms/帧）            │
│ ⑦ emit FrameReady               直连 → 就地执行 Present           │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────── VideoItem::Present（仍在视频线程）──────────────┐
│ pending_ = frame           只留最新一帧，旧的直接覆盖               │
│ frames_arrived_++          给 GUI 线程一个"有新帧"的信号           │
└──────────────────────────────────────────────────────────────────┘
                              │ GUI 线程 8ms 定时器发现计数变了 → update()
                              ▼
┌────────────────── 渲染线程 synchronize（sync 阶段）───────────────┐
│ TakePendingFrame()         取走最新一帧                           │
│ 三平面按行拷进 planes_[3]   5.2 MB，约 1 ms，帧引用随后释放         │
└──────────────────────────────────────────────────────────────────┘
                              ▼
┌────────────────── 渲染线程 render（GL 上下文当前）────────────────┐
│ glTexSubImage2D ×3         三平面各上传一张 LUMINANCE 纹理        │
│ GLSL 全屏四边形             BT.601 矩阵在 GPU 上转 RGB            │
│ 画进 FBO                    Qt 随后把 FBO 当纹理合成到窗口         │
└──────────────────────────────────────────────────────────────────┘
```

## Frame 的引用计数

`Frame` = 三个平面指针 + 三行字节跨度 + 一个 `shared_ptr<const void>`（持有 AVFrame，最后一个释放时调 `av_frame_free`）。

一帧的完整生命周期：

```
解码      owner 计数 1
frames    vector 存一份      2
emit      信号参数是值传递    3
Present   pending_ = frame   3 → Present 返回后信号参数析构 → 2
clear     下一轮清空 vector  1（只剩 pending_）
sync      取走 → 局部变量    1
sync 结束 局部变量析构        0 → av_frame_free
```

**全程没有像素拷贝**，只有原子引用计数。唯一的像素搬运是 synchronize 里那次 5.2 MB memcpy。

为什么要拷？因为不能跨帧持有 AVFrame：帧活过解码器销毁就是 use-after-free（踩过一次，崩在 `shared_ptr` 析构里）。用 1 ms 换掉一类崩溃。

## 为什么只留最新一帧

```
播放器（Player 项目）：必须每帧都播，还要和音频对齐 → 需要队列
投屏（本项目）       ：只要最新画面          → 队列只会增加延迟
```

`pending_` 就是一个变量，新帧直接覆盖。GUI 线程再慢，也不会积压——最多丢帧，不会延迟累积。

## H.264 解码的细节

- 配置包（SPS/PPS）单独一包，不产生画面，`Push` 里存起来拼到下一个普通帧前
- `avcodec_send_packet` 之后要循环 `receive_frame`：一次可能吐 0 帧（还在攒）或好几帧（追赶）
- `thread_count = 1`：帧级多线程在"只收到参数集还没有完整帧"时会让 `send_packet` 返回 `EAGAIN`，先单线程保稳
- 只接受 `AV_PIX_FMT_YUV420P`，别的格式直接报错——设备端固定这一种，出现别的说明编码参数被改过

## 耗时埋点

默认每秒打印一行（`QS_PERF=0` 关掉）：

```
[perf] 79 轮：GUI 排队 0.09 ms | 取帧 0.42 ms | 画一帧 0.63 ms | 两轮间隔 12.7 ms
```

四段的定义：

| 段 | 起点 | 终点 |
|---|---|---|
| 等数据 | 一轮开始 | 整帧从 buffer 里切走 |
| 解码 | 调用 Push | Push 返回 |
| 转换 | （GPU 后固定 0） | 以前是 sws_scale |
| 上屏 | updatePaintNode 取帧 | 三平面拷完 |
