# v0.4.3

发布 2026-11-27

修两个用久了会撞上的问题：关窗退不掉、配置文件越用越乱。

## 修了什么

### 关掉主窗口，进程还在后台

0.4.2 及更早的版本，点右上角关掉控制窗后：窗口没了、画面停了，但进程一直挂着。
以前只能关掉命令行窗口（等于强杀进程）或者任务管理器结束。

现在关窗后 **3 秒内进程自己退出**（这 3 秒里在跑 adb 收尾：`kill-server`、二次确认）。

根因是 Qt 场景图和 RHI 的析构会卡死：GUI 线程在等渲染线程，等了 60 秒也不返回。
清理做完后直接结束进程，不再走那段析构。

### `config.ini` 里出现 `%23%20%U6EDA...` 四行乱码

老模板用 `#` 写注释，而 QSettings 的 INI 格式只认 `;`。`#` 开头那行被当成键名，
下次写文件时整行转义成 `%23%20%U6EDA%U8F6E...` 这种看不懂的东西。

这一版：

| 项 | 结果 |
|---|---|
| 注释符号 | 全改 `;`，QSettings 正常识别 |
| 已经乱掉的文件 | 启动时自动清掉那些垃圾键 |
| 键是否齐全 | 每次启动按配置表重写一遍，`decode/threads`、`update/url` 这类以前漏掉的键也补齐了 |
| 用户改过的值 | 原样保留（实测 `max_fps=60` 不会被覆盖） |

改完之后 `config.ini` 长这样，每个键上面都有中文说明：

```ini
[video_wired]
; 长边上限，0 = 设备原生分辨率（更清晰，码率也要跟着涨）
max_size=0
; 码率，单位 bps
bit_rate=8000000
; 帧率上限：0 = 不限；应用锁 60Hz 时设 120 也只有 58 帧
max_fps=0
```

### 配置写错会告诉你

以前 `max_fps` 手滑写成 `abc`，程序静默按 0 处理，行为不对也查不出原因。
现在会打一条明确警告并按默认值处理，写超范围也会被钳到合理区间并告警。

## 内部整理（不影响使用）

- 配置项收敛成一张表（`settings_schema.h`），加一个配置从改四处变成改两处
- 删掉 163 行死代码：5 个没人调的函数、旧版本迁移逻辑、重复的宏定义
- 全量重建的 6 条 `C4005` 宏重定义警告清零

## 实测

```
关窗到进程消失：3.0 秒（0.4.2 是等 60 秒也不退）
config.ini 重生成：61 行，注释齐全，用户值保留
编译：0 错误 0 警告；单元测试 11/11
出画：连接完成 → 零拷贝管线就绪 → 截图正常
```

## 升级注意

- **建议老用户删掉 `config/` 目录下的 `config.ini` 和 `window.ini`**，让程序重新生成 ——
  这一版删掉了旧版本迁移逻辑，旧的 window.ini 里那些设置键不会再搬过来（留着也不影响运行）。
- 新装用户不受影响，首次启动生成的文件就是干净的。
- 命令行开关、老板键、快捷键这些设置如果之前调过，重生成后需要再设一次。

## 已知问题

- 关窗退出的做法是"清理完直接结束进程"，跳过了 Qt 的栈对象析构。如果以后升级 Qt 修掉了那个死锁，
  这段可以去掉，届时会再验一次。
- 硬解只支持 D3D12，驱动不支持的机器退软解。
