# QmlScrcpy 0.1.9

这一版主要修**画质设置不生效**这个硬伤，另外把"卡不卡、卡在哪"变成界面上能直接看到的东西。

## 新增

### 码率改成六档预设

以前要自己填一个 `8.0` 这样的小数，不知道填多少合适。现在直接选：

| 档位 | 码率 | 单帧约（60fps） | 适用 |
|---|---|---|---|
| 流畅 | 4 Mbps | 8 KB | 2.4G 无线、弱网 |
| 标准 | 8 Mbps | 17 KB | 无线默认 |
| 清晰 | 12 Mbps | 25 KB | 5G 无线、常看视频 |
| 高清 | 16 Mbps | 33 KB | 有线推荐 |
| 超清 | 20 Mbps | 42 KB | 有线、看细节 |
| 至臻 | 24 Mbps | 50 KB | 有线、视频/游戏 |

下拉右侧会实时显示当前档位在 60fps 下的单帧大小。选完点「应用并重连」立刻生效。

配置文件里写的是非预设值（比如 6M）时，下拉第一项会显示「当前（6 Mbps）」。

### 主窗显示 WiFi 健康度

无线连接时，主窗底部右侧多一块：

```
● WiFi 5G  -49 dBm  1297 Mbps 重传 13.1%
```

- **四档颜色**：绿（好）→ 黄（一般）→ 橙（差）→ 红（很差）
- **鼠标悬停**看详情：SSID、BSSID、WiFi 标准、频段、Tx/Rx 速率、累计重传/发送、累计丢包
- **有线连接不显示**

颜色判定同时看信号和重传率，谁差取谁：

| 等级 | 条件 |
|---|---|
| 绿 | RSSI ≥ -60 且重传 < 5% |
| 黄 | RSSI -60~-70 或重传 5~10% |
| 橙 | RSSI -70~-78 或重传 10~20% |
| 红 | RSSI < -78 或重传 > 20% 或出现丢包 |

**重传率按增量算**，不是累计值——累计值会越跑越平滑，看不出当下好坏。

这块的意义：以后无线觉得卡，先看它是不是黄的或橙的，就知道是链路问题还是我们的问题。

### 每秒统计增加实际码率与上屏间隔

```
[perf] 1s 到达 113 帧，上屏 113 帧，丢 0（0.0%），实际 1180 KB/s（9.4 Mbps）
[perf]     上屏延迟 <1.5ms 49% / 1.5~2.5ms 40% / 2.5~3.5ms 10% / >3.5ms 1%，最大 4.0 ms
[perf]     到达间隔 <8.5ms 57% / 8.5~17ms 43% / 17~34ms 1% / >34ms 0%
[perf]     上屏间隔 <8.5ms 55% / 8.5~17ms 44% / 17~34ms 1% / >34ms 0%
```

- **实际码率**：这一秒从链路真正收到多少字节，和设置值对比就能看出编码器有没有超发
- **上屏间隔**：和到达间隔并排看，两者接近说明客户端没有额外引入抖动

## 修复

| 问题 | 影响 |
|---|---|
| **设置里改码率不生效** | `window.ini` 里的键名是 `bitrate`，代码读的是 `bit_rate`，键名对不上，导致界面里设的 24M 一直回落到 `config.ini` 的 8M |
| **启动白屏闪一下** | 主窗和设置窗第一次显示约有 1 秒白底，现在首帧透明后再显现 |
| **设置窗按钮被裁掉** | 窗口太窄，「应用并重连」「保存快捷键」显示不全，已加宽到 620 |
| **码率下拉是系统白底** | 改成自绘深色样式，和整体主题一致 |
| **「应用并重连」看不出有没有生效** | 现在未应用时按钮显示「应用并重连 *」 |

## 性能

### 客户端一帧延迟 6.3ms → 2.4ms

Qt 的 `QWindow::requestUpdate()` 在多数平台上由一个 **5ms 的 GUI 线程定时器**支撑，这 5ms 直接加在一帧到上屏的延迟上。用 `QT_QPA_UPDATE_IDLE_TIME=0` 关掉这个余量后：

| 配置 | 一帧到上屏（中位） |
|---|---|
| 默认 | 6.26 ms |
| **关掉余量** | **1.89 ms** |

静止画面下 CPU 没有明显增加。

### 无线 120Hz

应用自身跑 120Hz 时能稳定跟上（抖音切 120Hz 实测 97fps）；应用锁 60Hz 时设 `max_fps=120` 也只有 58 帧——**帧率参数是上限，不是目标**。

## 内部改动（用户看不到）

- 投屏行为拆成 `VideoController`，主窗只管连接和设置
- `main.cpp` 入口拆成 9 个函数
- `window.ini` 改全键位模板，去掉历史迁移代码
- 观测分层：默认每秒四行统计，逐帧九段明细用 `QS_TRACE_FRAMES=1` 打开

## 已知限制

- **无线码率建议 8~12M**：24M 在 WiFi 上会排队，表现为帧到达不匀（抖动），此时 WiFi 标记会变橙或变红
- **WiFi 标记为绿色时，无线流畅度接近有线**；变橙变红就说明链路在重传
- `max_fps` 填 120 只在应用自身跑 120Hz 时有意义

## 升级说明

覆盖安装即可，配置文件保留。如果之前手动改过 `window.ini` 的 `bitrate` 键，新版不再识别该键（统一为 `bit_rate`），请用设置界面重新选一次码率。
