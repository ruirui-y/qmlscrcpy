# v0.3.1

## 本次更新

### 解码设置搬进界面

以前只能改 `config.ini`，现在设置窗里直接调：

| 设置项 | 说明 |
|---|---|
| **解码方式** | 硬解（GPU）/ 软解（CPU），切换后自动重连 |
| **软解线程数** | 1~8，默认 4。少了解码慢、多了攒帧变多 |
| **读回方式** | 同步（更跟手）/ 异步（CPU 不等 GPU，画面晚一帧） |

硬解时线程数输入框会自动置灰。

### 修复：切回硬解后画面变红

从软解切到硬解，画面会一直蒙一层红色。原因是渲染器的纹理只在「尺寸变化」时重建，而两种解码方式的 UV 平面尺寸一样、**格式不同**：

```
软解 UV：GL_LUMINANCE        每纹素 1 字节（只装 U）
硬解 UV：GL_LUMINANCE_ALPHA  每纹素 2 字节（U + V）
```

尺寸判断通过 → 没重建 → 1 字节的纹理被塞 2 字节数据 → 颜色错乱。

现在把「格式」也纳入重建条件，切换不再红屏。

### 内部优化（感知不到，但更稳）

- 帧缓冲池：不再每帧分配/释放 5MB，长时间运行更稳
- 解码耗时探针改成三段（准备 / 等 Map / 读），日志更准
- 删掉硬解路径里约 170 行没用的转色代码

## 性能参考（1264×2780 硬解）

| 模式 | 单帧 CPU 时间 | 画面延迟 |
|---|---|---|
| 同步读回（默认） | 3.3ms | 无额外 |
| 异步读回 | 1.65ms | +1 帧 |

> 提示：NVIDIA 控制面板把 `QmlScrcpy.exe` 的电源管理模式设为「最高性能优先」，
> PCIe 才会跑在 Gen4，读回快一倍（3.0ms → 1.3ms）。默认省电模式下会慢一些。

软件 GL 兜底（opengl32sw）、D3D12 编译后端（dxcompiler）和 Qt 的调试器插件（qmltooling），
图片格式插件只留 png/jpeg/gif/ico/svg。功能没有任何删减。
