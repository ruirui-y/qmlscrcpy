# v0.4.2

发布 2026-11-24

修 0.4.1 的两个 bug，并清掉一段 OpenGL 时代的死代码。

## 修了什么

### 「命令行」开关重启后失效（0.4.1 引入）

0.4.1 把设置全部收进 `config.ini` 时，这个开关**只改了一半**：

```
读：config.ini   ← 对
写：window.ini   ← 错
```

后果比“重启不生效”更糟：下次启动的配置迁移看到 `window.ini` 里这个键，
而 `config.ini` 里已经有默认的 `false`，按“不覆盖”规则跳过，**然后把 `window.ini` 里的键删掉**——
你选的 `true` 被直接丢弃，永远不生效。

这一版读写都走 `config.ini`。如果你之前在 0.4.1 里开过命令行窗口，需要**再打开一次**。

### 偶发一帧画面撕裂（0.4.1 引入）

0.4.1 为了省 1ms 延迟，把“等解码完成”从渲染线程挪到解码线程。问题在于两个等待不等价：

| 等待 | 保证什么 |
|---|---|
| `queue->Wait`（渲染线程） | 这条队列的采样命令一定在解码之后执行 |
| `SetEventOnCompletion`（解码线程） | 围栏值到了（不等于 GPU 已经执行完所有后续命令） |

实测出现过一次“半帧新半帧旧、色度发绿”的画面，只闪一帧。这一版补了 GPU 侧兜底：
围栏没到就补一次 `queue->Wait`，到了就什么都不做。**延迟收益没有回吐**（实测转色等围栏 157us，与 0.4.1 持平）。

### 删掉 OpenGL 时代的死代码

`main.cpp` 里还留着 `QSurfaceFormat` 设 GL 2.0 / NoProfile / swapInterval=0，注释写着
“VideoItem 是 QQuickFramebufferObject”。现在走 RHI + D3D12，这段完全不参与。

顺带查清一件事：`setSwapInterval(0)`（注释说“关垂直同步：投屏延迟第一刀”）
**在 D3D12 下从来没生效过** —— 全仓库没有任何地方设 `QRhiSwapChain::NoVSync`，垂直同步一直开着。

## 实测

```
[convert] 153 帧：录命令+提交 97 us，等围栏 157 us
[perf] 1s 到达 110 帧，上屏 109 帧，丢 0（0%）
断言 0
```

## 已知问题

- 撕裂的兜底只覆盖“采样这一刻”，不覆盖“解码器复用同一张纹理”；后者靠 owner 持有 AVFrame 引用拦住
- 硬解只支持 D3D12，驱动不支持的机器退软解

## 升级注意

- 直接覆盖安装
- 如果你在 0.4.1 里开过「命令行」窗口，升级后需要再打开一次（旧选择已被丢弃）
- 配置文件结构不变，不需要重置
