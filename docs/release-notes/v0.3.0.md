# QmlScrcpy 0.3.0

这一版是平台级更新：**迁移到 Qt 6.8 + 换 FFmpeg 6.1.3 + 启用 GPU 硬解**。

## 迁移到 Qt 6.8

| 项 | 变化 |
|---|---|
| 框架 | Qt 5.15.2 → **Qt 6.8.3**（MSVC 2022 64 位） |
| 解码库 | FFmpeg 4.4 → **6.1.3**（avcodec-60） |
| 渲染后端 | 显式指定 OpenGL（Qt6 在 Windows 默认挑 D3D11，会让 FBO 画面全黑） |
| 构建 | 新增 `qt6-debug` / `qt6-release` 预设；`build/windows-*`（Qt5）保留可对照 |

迁移踩的坑都记在 `docs/Qt6迁移.md`：`QObject::connect` 配 `Qt::UniqueConnection` 在 Qt6 里直接断言、每帧 `update()` 重入导致爆栈、Qt6 控件样式不再允许自定义 `background`。

## 新增：GPU 硬解

`config.ini` 新增开关：

```ini
[decode]
hardware=1     ; 1 = D3D11VA 硬解（默认），0 = FFmpeg 软解
```

硬解链路：

```
收包 → D3D11VA 解码（GPU）
     → 拷进自己复用的暂存纹理（省掉 FFmpeg 每帧新建纹理）
     → 读回 NV12 → 着色器转 RGB
```

两个关键点：

- **自己枚举 DXGI 适配器**建设备。本机装了两个虚拟显示适配器（IddSampleDriver / OrayIddDriver），FFmpeg 默认挑第一个会直接失败
- **NV12 一个数组切片就是一个子资源**，之前按 `slice*2` 去拷会拿到全 0，画面是一片深绿

## 为什么默认硬解

软解把解码放进 4 个 worker 线程，主线程不阻塞，但**帧级多线程会攒帧**，画面比最新收到的帧落后 2~3 帧（60fps 下约 50ms）。表现为：

| 场景 | 软解 | 硬解 |
|---|---|---|
| 打字 | 按一个字母要等一下才出现 | 跟手 |
| 切换屏幕 | 有帧缓动 | 无 |

解码探针的数字（软解 90us vs 硬解 6.2ms）**不能用来选方案**，它只量调用线程等待，量不到流水线延迟。详见 `docs/解码链路.md` 第十二节。

## 修复

| 问题 | 原因 |
|---|---|
| 启动后「adb devices 失败：adb 命令超时」 | 只认 `Tools\adb.exe` 后，第一次调用要换掉别的版本的 adb server，耗时 5.1 秒撞上 5 秒超时。改为启动时后台预热 + 超时放宽到 15 秒 |
| 构建时报「找不到 avcodec-58.dll」 | 换 FFmpeg 6.1 后运行库编号变了，部署改成整目录 glob |
| 编辑模式键位圆点跑到画面外 | 叠加层还没尺寸时算坐标，改成绑定 + 拖动时断绑定 |
| Space 键映射无效 | 配置存小写 `space`，虚拟键码表是大写，统一按小写查 |

## 已知限制

- 零拷贝（`WGL_NV_DX_interop2`）**未完成**：现代码里保留了 VideoProcessor 和 interop 骨架，但原生纹理绘制会崩在 `wglDXUnlockObjectsNV`，根因是解码线程写、渲染线程锁之间没有帧序号同步
- Qt6 下控件走平台原生样式，自定义 `background` 失效，外观和 Qt5 版不完全一致
- 设备查询仍在主线程同步执行，adb 冷启动时界面会卡 1 秒左右

## 升级说明

覆盖安装即可，配置保留。新增 `config.ini` 的 `[decode] hardware` 段和仓库内 `Tools/adb.exe`。
