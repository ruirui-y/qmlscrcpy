# 老板键

按一次藏起所有窗口，再按一次恢复。默认 `Ctrl+Alt+B`。

名字来自"老板来了赶紧按一下"，最早是电脑上快速隐藏游戏/聊天窗口的快捷键——不是给老板用的。

## 1. 为什么不用 Win+D

Win+D 是系统级的"显示桌面"，它把所有程序的窗口都最小化。我们要的是**只藏自己**：

| | Win+D | 我们的老板键 |
|---|---|---|
| 影响范围 | 所有程序的窗口 | 只有 QmlScrcpy 的两扇窗 |
| 恢复 | 再按一次 Win+D（但如果中途点了别的窗口就乱了） | 再按一次同一个热键，恢复原来的可见性 |
| 出现在任务栏 | 还在（能看到图标） | 窗口直接 `hide()`，任务栏里也没了 |

## 2. 怎么实现

**全局热键**：窗口没有焦点时也要能收到按键，只能用 Win32 的 `RegisterHotKey`：

```cpp
::RegisterHotKey(nullptr, kHotkeyId, spec.modifiers_ | MOD_NOREPEAT, spec.virtual_key_);
```

- `MOD_NOREPEAT`：按住不放只触发一次，否则会疯狂切换
- `UnregisterHotKey`：程序退出前必须调，不然这个组合键会一直被系统认为被占用

按键消息从 Qt 的 `QAbstractNativeEventFilter` 里截：

```cpp
if (msg->message == WM_HOTKEY && static_cast<int>(msg->wParam) == kHotkeyId)
{
    emit Triggered();
    return true;    // 吃掉，别再往窗口发
}
```

'**隐藏/恢复**：

```cpp
// 藏：只藏登记过的窗口
for (const QPointer<QWindow> &window : app_windows_) {
    if (!window.isNull() && window->isVisible()) { hidden_windows_.append(window); window->hide(); }
}
'
// 恢复：只 show 刚才藏的那些
for (const QPointer<QWindow> &window : hidden_windows_) { window->show(); }
```

用 `QPointer` 是因为窗口可能被 QML 销毁（比如投屏窗断开后隐藏），裸指针会变成野指针。

### 为什么不用 topLevelWindows()

第一版遍历 `QGuiApplication::topLevelWindows()`，结果**只藏住了主窗，投屏窗没反应**。

原因：投屏窗在 QML 里声明在 `MainWindow` 内部，`QWindow::parent()` 非空 → 它不算 top-level 窗口，不在那个列表里。我们虽然把 `transientParent` 置空了，但 QObject 父对象还在。

改成**登记制**：两个窗口在 `Component.onCompleted` 里自己报到。

```qml
// MainWindow.qml
deviceController.RegisterWindow(controlWindow)
deviceController.RegisterWindow(videoWindow)

// VideoWindow.qml（自己再登记一次，防止创建时机晚于主窗）
deviceController.RegisterWindow(videoWindow)
```

控制器用 `QList<QPointer<QWindow>> app_windows_` 存着，老板键只操作这份名单。

## 3. Qt 会把隐藏的窗口再显示一次

**现象**：按老板键后主窗消失了，**投屏窗闪一下又回来了**。

**定位**：给 `RegisterWindow` 挂 `QWindow::visibilityChanged` 打印，再在隐藏后 300ms 复查一次：

```
[boss] 可见性变化 "QmlScrcpy" -> 0                    ← 藏成功（0 = Hidden）
[boss] 藏了 "QmlScrcpy" 藏后 visible false
[boss] 可见性变化 "QmlScrcpy — e77121ed" -> 0          ← 投屏窗也藏了
[boss] 可见性变化 "QmlScrcpy — e77121ed" -> 2          ← 立刻又回到 Windowed！
[boss] 300ms 后 "QmlScrcpy — e77121ed" visible true
```

主窗没有这个现象，只有投屏窗（QQuickFramebufferObject 的渲染窗口）会。

**原因**：Qt 在处理窗口激活/曝光事件时，会把仍有内容的 QQuickWindow 重新 `show()` 一次。这次 show 来自 Qt 内部，不是我们的代码。

**解法**：藏完等下一轮事件循环再补一刀：

```cpp
window->hide();

// Qt 会在窗口隐藏后因为激活/曝光事件把它重新显示一次（投屏窗实测必现），
// 这里等下一轮事件循环再补一刀，之后就稳住了
QTimer::singleShot(0, this, [this]() {
    if (!boss_hidden_) { return; }
    for (const QPointer<QWindow> &window : hidden_windows_)
    {
        if (!window.isNull() && window->isVisible()) { window->hide(); }
    }
});
```

**验证方式**：用 Win32 `EnumWindows` + `IsWindowVisible` 枚举程序所有窗口，按键前后各看一次：

```
按键之前：      478x938 [投屏窗] visible=True   616x289 [主窗] visible=True
第一次按键后：  478x938 [投屏窗] visible=False  616x289 [主窗] visible=False
第二次按键后：  478x938 [投屏窗] visible=True   616x289 [主窗] visible=True
```

## 4. 在界面上改键

主窗右上角有个显示当前组合的按钮（默认 `Ctrl+Alt+B`），点开是一行输入框：

```
┌──────────────────────────────┐
│ 老板键组合（至少带一个修饰键）  │
│ [Ctrl+Alt+B              ]   │
│ 可用：Ctrl/Alt/Shift/Win 组合 │
│      A~Z、0~9、F1~F24、Space  │
│         [   应用   ]          │
└──────────────────────────────┘
```

点「应用」做三件事：解析 → `BossKey::Bind()` 重新注册 → 写进 `window.ini`。

**失败要能回滚**：`Bind()` 内部会先 `Unbind()` 旧的，如果新组合被别人占用，旧的就丢了。所以注册失败时会把上一次的组合重新绑回去，状态栏提示：

```
Ctrl+Shift+K 可能被别的程序占用，已保留 Ctrl+Alt+B
```

## 5. 配置

`config.ini`：

```ini
[ui]
# 老板键：格式 Ctrl+Alt+B / Ctrl+Shift+F9 / Alt+Space
boss_key=Ctrl+Alt+B
```

界面里改过的写 `window.ini`，优先级高于这里的 `config.ini`（和画质参数一个规则）。手改 `config.ini` 后重启生效；注册失败会在日志里写一行：

```
[app] 老板键注册失败，检查 config.ini 的 ui/boss_key：Ctrl+Alt+B
```

常见原因：这个组合被别的程序占了（输入法、录屏软件最爱抢 `Ctrl+Alt+*`）。

支持的写法：

| 修饰键 | 主键 |
|---|---|
| `Ctrl` / `Control` | 字母 `A`~`Z` |
| `Alt` | 数字 `0`~`9` |
| `Shift` | `F1`~`F24` |
| `Win` / `Meta` | `Space` / `Tab` / `Esc` / `Insert` / `Delete` / `Home` / `End` / `PageUp` / `PageDown` |

**必须至少带一个修饰键**——单键热键会把那个键从整个系统里抢走，不能允许。

## 6. 断线时自动恢复

如果按了老板键、窗口正藏着，这时设备断开触发 `TearDown()`，窗口会被自动 `show()` 回来：

```cpp
if (boss_hidden_) { /* 逐个 show，然后清状态 */ }
```

否则用户会面对"程序还在跑但没有任何窗口"，只能去任务管理器杀进程。

## 7. 测试

解析逻辑有单测（`tests/tst_hotkey.cpp`，5 个用例）：正常解析、功能键、只有修饰键、未知键名、拼回文本。

热键本身要在真机上手测——`RegisterHotKey` 成功只能说明系统接受了这个组合，按下去有没有反应得实际按。
