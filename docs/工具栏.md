# 工具栏

投屏窗右侧那条竖栏，放常用操作。**它是一扇独立的无边框窗口**，不是嵌在画面里的控件。

## 为什么是独立窗口，不是嵌进去

第一个版本想嵌在画面里，量了一下发现代价不对：

```
嵌进画面：
   窗口宽 = 帧宽/DPR + 48
   → 画面区域被切窄，要么压缩变形，要么整窗缩小时画面跟着糊
   → 缩放把手、拖动、1:1 清晰度全要重算

独立窗口：
   画面区尺寸完全不动，工具栏只是"旁边多出来的一扇窗"
   → 贴紧靠 x/y 绑定，跟随靠绑定，1:1 一点不受影响
```

所以现在画面永远是 `帧尺寸 / devicePixelRatio`，工具栏宽度固定 64px 贴在右边。

## 长什么样（按钮从上到下）

```
┌──────────────────────────────┐┌──────────┐
│  ◢  QmlScrcpy — 投屏   — ✕   ││   主窗    │\n││   返回    │
├──────────────────────────────┤│   任务    │ ← APP_SWITCH
│                              ││  滑动 60  │ ← 滚动/滑动，显示当前像素
│                              ││  −5  │ +5 │ ← 粗调
│        画面（1:1）            ││  −1  │ +1 │ ← 微调（只在滑动模式出现）
│                              ││  音量 +   │
│                              ││  音量 −   │
│                              ││   旋转    │
│                              ││   截图    │
│                              ││  息屏/亮屏 │
│                              ││   置顶    │
│                              ││   全屏    │
└──────────────────────────────┘└──────────┘
```

## 按钮与底层消息

| 按钮 | 底层 | 说明 |
|---|---|---|
| 返回 | `INJECT_BACK_OR_SCREEN_ON` | 按下+抬起两条；息屏时还能顺手点亮屏幕 |
| 任务 | `INJECT_KEYCODE` 187 | `KEYCODE_APP_SWITCH`，弹最近任务 |
| 滚动/滑动 | 本地状态 | 切 `WheelMode`，写 `window.ini` |
| −5 / +5 | 本地状态 | 滑动像素粗调 |
| −1 / +1 | 本地状态 | 滑动像素微调 |
| 音量 ± | `INJECT_KEYCODE` 24 / 25 | 按下+抬起各一条 |
| 截图 | 本地 | `grabWindow()` → `screenshots/`，同时进系统剪贴板 |
| 息屏/亮屏 | `INJECT_SET_SCREEN_POWER_MODE` | 0 关 1 开，不动锁屏 |
| 置顶 | 本地 | `WindowStaysOnTopHint`，投屏窗一起置顶 |
| 全屏 | 本地 | `FullScreen` ↔ `Windowed` |

**为什么不用 `KEYCODE_MENU`(82)**：现代安卓应用基本不响应它，点了没任何反应。多任务切换要用 `KEYCODE_APP_SWITCH`(187)。

## 提示词

每个按钮都有 `ToolTip`，鼠标停 400ms 出现：

```qml
ToolTip.visible: area.containsMouse && button.tip.length > 0
ToolTip.text: button.tip
ToolTip.delay: 400
```

「滚动/滑动」的提示会跟着当前模式变，告诉用户点一下会切到哪边。

## 为什么没有「主窗」和「旋转」

| 按钮 | 为什么删 |
|---|---|
| 主窗 | 调了两轮（QML `raise()`、C++ `ShowControlWindow()`）都没能稳定把窗口拉回前台，Windows 前台锁 + 多窗口组合太不可控，删掉改用任务栏 |
| 旋转 | 消息本身是对的（1 字节 type=11 无负载，符合 scrcpy 协议），触摸/音量/息屏都正常说明控制通道没问题；卡在服务端：scrcpy 的旋转靠隐藏 API 反射，Android 15 上会被拦。设备 `accelerometer_rotation=0`、`user_rotation=1` 也印证了没有别的口子 |

## 贴紧与跟随

```qml
// 贴住投屏窗右边缘；快到屏幕右边就翻到它左边
function followX() {
    const right = target.x + target.width
    return (right + width > Screen.desktopAvailableWidth) ? Math.max(0, target.x - width) : right
}

x: followX()
y: followY()
height: target.height
```

早期版本在 `target.width` 后面加了 6px 间距，看着有一条缝，已经去掉。

## 拖动

工具栏背景（按钮之间的空白）上有一个拖动区，**拖它等于拖投屏窗**：

```qml
onPositionChanged: {
    if (!pressed || !toolWindow.target) {
        return
    }
    const current = dragArea.mapToGlobal(mouse.x, mouse.y)
    toolWindow.target.x = pressWindow.x + (current.x - pressGlobal.x)
    toolWindow.target.y = pressWindow.y + (current.y - pressGlobal.y)
}
```

工具栏自己不用改 x/y——它绑在投屏窗上，投屏窗一动它自动跟过去。

> 第一版做成"拖工具栏 = 把工具栏单独拆走，双击贴回"。用户要的是"拖工具栏 = 拖整个投屏窗"，改成了现在这样。

## 滑动像素

范围 **10 ~ 300**：

| 太小 | 太大 |
|---|---|
| 系统触摸阈值一般 8~16px，低于它会被当成"点击" | 一格滚轮翻过一大段，很难精确定位 |

优先级：

```
工具栏调过的（window.ini 的 [input] drag_pixels）
    > config.ini 的 [input] drag_pixels（默认值）
    > 60（兜底）
```

## 踩过的坑

| 现象 | 原因 | 解法 |
|---|---|---|
| 工具栏根本不出现 | `MainWindow.qml` 里的实例化被脚本替换静默跳过 | 用编辑工具补，并靠枚举窗口确认 |
| 整个界面都没了 | `Layout.fillWidth` 用在 `Column` 里，又没 `import QtQuick.Layouts` → QML 编译失败，`Type ToolBarWindow unavailable` 连带控制窗也不显示 | 改成 `width: parent.width` |
| `Method names cannot begin with an upper case letter` | QML 函数名不能大写开头（`FollowX` / `AttachToTarget`） | 改成 `followX` / `attachToTarget` |
| 改了没生效 | 构建失败但旧进程还在跑，看到的是上一版 | 先确认构建成功、再确认 pid 变了 |

## 文件

| 文件 | 职责 |
|---|---|
| `qml/ToolBarWindow.qml` | 窗口本体：布局、按钮、拖动区 |
| `qml/MainWindow.qml` | 实例化工具栏并把自己的投屏窗交给它 |
| `src/device_controller.*` | 按钮背后的动作（返回/任务/音量/旋转/截图/息屏/滑动像素） |
| `libs/input/touch_controller.*` | 滚动/滑动两种滚轮发法 |
| `src/app_settings.*` | 滑动像素与滚轮模式的读写 |
