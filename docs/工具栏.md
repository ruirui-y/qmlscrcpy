# 工具栏

投屏窗右侧那条竖栏，放常用操作。**它和画面在同一扇窗口里**，是 `RowLayout` 的第二个子元素。

## 为什么搬回窗口里（走了个弯路）

| 版本 | 做法 | 结果 |
|---|---|---|
| 第一版 | 嵌在窗口里 | 窗口按帧比例算，插进 64px 后画面比例变了，当时图省事拆出去 |
| 第二版 | 拆成独立窗口，`x = target.x + target.width` 贴上去 | 画面比例干净了，但引出一串跨窗口问题 |
| 现在 | 搬回同一扇窗口 | 跨窗口问题全部消失 |

第二版具体踩的坑：

```
位置跟随    x/y 绑定，投屏窗一移动工具栏要跟着算
最小化同步  两个 HWND，visible 管不了最小化，得监听 visibility 手动同步
owner 关系  QML 窗口声明在另一窗口里会继承 transientParent，主窗最小化把它们一起藏掉
贴紧缝隙    6px 的间距算错过一次，看起来有条缝
```

共同点：**两个窗口之间没有任何内建约束，全靠手写代码补偿**。搬回一扇窗口后，布局由 `RowLayout` 保证，上面四条一个都不用写。

全屏时工具栏**保持在右侧**：一开始试过全屏收起工具栏（`visible: visibility !== Window.FullScreen`），实际用起来"全屏后按钮全没了"很别扭，取消了。

## 按钮与底层消息

| 按钮 | 底层 | 说明 |
|---|---|---|
| 返回 | `INJECT_BACK_OR_SCREEN_ON` | 按下+抬起两条；息屏时还能顺手点亮屏幕 |
| 任务 | `INJECT_KEYCODE` 187 | `KEYCODE_APP_SWITCH`，弹最近任务 |
| 滚动/滑动 | 本地状态 | 切 `WheelMode`，写 `window.ini` |
| −5 / +5 | 本地状态 | 滑动像素粗调 |
| −1 / +1 | 本地状态 | 滑动像素微调 |
| 音量 ± | `INJECT_KEYCODE` 24 / 25 | 按下+抬起各一条 |
| 截图 | 本地 | `grabWindow()` → `screenshots/`，同时进系统剪贴板 |
| 息屏/亮屏 | `INJECT_SET_SCREEN_POWER_MODE` | 0 关 1 开，不动锁屏 |
| 置顶 | 本地 | `WindowStaysOnTopHint` |
| 全屏 | 本地 | `FullScreen` ↔ `Windowed`，工具栏保持可见 |
| 复位 | 本地 | 删掉当前姿势的尺寸记录，恢复默认（横屏 900×400，竖屏按画面比例） |

**为什么不用 `KEYCODE_MENU`(82)**：现代安卓应用基本不响应它，点了没任何反应。多任务切换要用 `KEYCODE_APP_SWITCH`(187)。

## 提示词：不走浮层，用整窗宽的提示条

每个按钮有 `tip`，鼠标悬停时写进窗口自己的 `hint` 属性：

```qml
MouseArea {
    hoverEnabled: true
    onEntered: videoWindow.hint = button.tip
    onExited: videoWindow.hint = ""
}
```

提示**不挤进标题栏**（标题栏只有视频区那么宽，长句会被省略号截断），而是盖一条横跨"视频区 + 工具栏"的提示条：

```qml
Rectangle {
    anchors.left: parent.left
    anchors.right: parent.right
    anchors.top: parent.top
    height: 30
    color: "#12233a"
    visible: videoWindow.hint.length > 0
    z: 10

    Text { anchors.fill: parent; text: videoWindow.hint; color: "#9cc4ff"; elide: Text.ElideRight }
}
```

标题栏本身只显示 `设备名 + fps + 分辨率`，两者互不干扰。

为什么不用 `ToolTip`：Qt 5.15 上试了三种写法——默认样式在 64px 窗口里被挤成竖排、`popupType: Popup.Window` 启动栈溢出、只改背景又撞 `QVector` 断言。同一个组件连续三次以不同方式崩，说明它在这个用法下不可靠，于是换掉。
## 光标反馈

所有可点区域都要给鼠标形状，否则只有悬停变色，看起来"不知道该不该点"：

| 区域 | 光标 | 为什么 |
|---|---|---|
| 工具栏按钮 | `Qt.PointingHandCursor` | 可点击 |
| 标题栏最小化 / 关闭 | `Qt.PointingHandCursor` | 可点击 |
| 标题栏空白处 | `Qt.SizeAllCursor`（四向） | 能拖动窗口 |
| 工具栏按钮之间的空地 | `Qt.SizeAllCursor` | 也能拖窗口 |
| 右下角 / 左上角把手 | `Qt.SizeFDiagCursor`（斜向双箭头） | 能缩放 |

拖动区用四向箭头而不是手型，是为了和"点一下就执行"的按钮区分开。

## 尺寸怎么算

```
窗口宽 = 画面宽 + 64
wantWidth  = 帧宽 / DPR + toolBarWidth
wantHeight = (wantWidth - toolBarWidth) * 帧高/帧宽
```

画面区域仍然是 1:1 的帧比例，工具栏只是"多出来的 64px"。竖屏和横屏各记一套窗口尺寸，见 [窗口几何](窗口几何.md)。

## 拖动

两个地方都能拖整扇窗口：

- **标题栏**：常规入口
- **工具栏按钮之间的空地**：`toolBarDragArea` 铺满工具栏列，按钮自己的 MouseArea 声明在后面会先吃掉点击，所以只有空地生效

没有"拖工具栏挪投屏窗"这种跨窗口联动——因为本来就是同一个窗口。

## 滑动像素

范围 **10 ~ 300**：

| 太小 | 太大 |
|---|---|
| 系统触摸阈值一般 8~16px，低于它会被当成"点击" | 一格滚轮翻过一大段，很难精确定位 |

优先级：

```
工具栏调过的（window.ini 的 [input] drag_pixels）
    > config.ini 的 [input] drag_pixels（默认值）
    > 60（兜底）
```

## 为什么没有「主窗」和「旋转」

| 按钮 | 为什么删 |
|---|---|
| 主窗 | 调了两轮（QML `raise()`、C++ `ShowControlWindow()`）都没能稳定把窗口拉回前台，Windows 前台锁 + 多窗口组合太不可控，删掉改用任务栏 |
| 旋转 | 消息本身是对的（1 字节 type=11 无负载，符合 scrcpy 协议），触摸/音量/息屏都正常说明控制通道没问题；卡在服务端：scrcpy 的旋转靠隐藏 API 反射，Android 15 上会被拦 |

## 文件

| 文件 | 职责 |
|---|---|
| `qml/VideoWindow.qml` | 窗口本体 + 画面 + 工具栏（`component ToolButton` 和按钮列表都在这） |
| `qml/MainWindow.qml` | 控制窗：连接管理，只负责拉起投屏窗 |
| `src/device_controller.*` | 按钮背后的动作（返回/任务/音量/截图/息屏/滑动像素） |
| `libs/input/touch_controller.*` | 滚动/滑动两种滚轮发法 |
| `src/app_settings.*` | 滑动像素与滚轮模式的读写 |
