# 按键映射

## 一、这一阶段要做什么

把键盘按键映射成手机屏幕上的触摸，让手游能用键鼠。范围分三种键位：

| 类型 | 用途 | 行为 |
|---|---|---|
| 点按 tap | 技能、平A | 按下立刻抬起（延迟 40ms 更稳） |
| 按住 hold | 蓄力、持续开火 | 按下保持，松开才抬起 |
| 摇杆 steer | 走位 | 按中心落指，方向键推出去，松手回中 |

## 二、怎么做的

三层，互相不耦合：

```
┌──────────────────────────────────────────────────┐
│ QML  VideoWindow.qml                             │
│   工具栏三态按钮（关 / 玩 / 编）+ 叠加层编辑器   │
└───────────────────┬──────────────────────────────┘
                    │ videoController.mapMode / keyMapItems
┌───────────────────▼──────────────────────────────┐
│ VideoItem（ui/video_item.cpp）                   │
│   三态开关、16ms 轮询物理按键、动作分发          │
└───────────────────┬──────────────────────────────┘
                    │ Press/Release/Tick → KeyMapAction
┌───────────────────▼──────────────────────────────┐
│ KeyMapEngine（libs/input/keymap_engine.*）       │
│   按键 → Down/Move/Up + 归一化坐标               │
├──────────────────────────────────────────────────┤
│ KeyMap（libs/input/keymap.*）                    │
│   数据结构 + JSON 读写，不碰界面和协议           │
├──────────────────────────────────────────────────┤
│ TouchController（libs/input/touch_controller.*） │
│   NormalizedTouch() → scrcpy 控制消息            │
└──────────────────────────────────────────────────┘
```

**坐标一律归一化 0~1**，换分辨率、横竖屏都不用改配置。

配置文件：`config/keymap/<设备串号>.json`，冒号换成下划线。

## 三、写完为什么不是理想效果

前五版全部失败，坑一个接一个：

| 版 | 现象 | 根因 |
|---|---|---|
| 1 | 按 Q/W/E 完全没反应 | 配置存 `"q"`，Qt 给 `"Q"`，`==` 不相等 |
| 2 | 编辑模式看不到已有键位 | `Repeater` 建 delegate 时叠加层宽度还是 0，坐标算成 `(-17,-17)` 跑到画面外 |
| 3 | 拖动圆点会跳回原位 | `x/y` 是绑定，拖动的赋值立刻被绑定值覆盖 |
| 4 | 拖动时圆点乱跳 | `onPositionChanged` 里写回模型触发 `Repeater` 重建 |
| 5 | 按住摇杆 0.5 秒自动抬 | Windows 自动重复成对发 Press/Release，`keyReleaseEvent` 没过滤 |
| 6 | 过滤后点按类连续触发 | `isAutoRepeat()` 在 Windows 上不可靠，重复的按下报 `false` |
| 7 | 方向键松不开 | 用物理状态无条件吞掉松开，真松手那一瞬间状态还没更新 |

## 四、怎么定位的

**全靠日志**，每一版都加了 `[keymap]` 前缀的行：

```
[keymap] press "W" actions 2
[keymap] release "W" actions 2
[keymap] release "W" actions 0     ← 这行出现几十次就说明在刷假松开
```

关键证据链：

1. 第一次实验：`press` 之后 0.5 秒出现 `release actions 2`，之后每 33ms 一条 `release actions 0`
2. 数数字对上了：**500ms 首延迟 + 30 次/秒 = Windows 默认键盘重复速率**
3. 于是确认不是我们的逻辑，是自动重复事件漏进来了

中间还试过三种判断方式，都不行：

| 判断依据 | 结果 |
|---|---|
| `event->isAutoRepeat()` | Windows 上重复按下报 false |
| 自己维护 `QSet<int> pressed_keys_` | 假 Release 会把它删掉，下一个重复按下又被当成新按键 |
| `GetAsyncKeyState` 在事件回调里查 | 真松手瞬间状态还没更新，松开被吞，角色一直走 |

## 五、怎么解决的

**不再信任任何按键事件，改成 16ms 轮询硬件状态**：

```cpp
// 16ms 轮询：只有"按下状态"发生变化才发触摸，自动重复事件完全不影响这里
for (const QString &name : key_map_engine_.TrackedKeys())
{
    const int vk = VkForName(name);
    const bool down = (::GetAsyncKeyState(vk) & 0x8000) != 0;
    if (down == polled_keys_.contains(name)) continue;

    if (down) { polled_keys_.insert(name); Dispatch(Press(name)); }
    else      { polled_keys_.remove(name); Dispatch(Release(name)); }
}
```

`keyPressEvent` / `keyReleaseEvent` 里对映射键**只做一件事：吞掉**，不再参与判断。

两个配套细节：

- **键名 → 虚拟键码**的映射表统一按小写查（配置里可能是 `space` 或 `Space`）
- 点按类按下后 **40ms 再补抬起**，按太快游戏会当成没按下

## 六、最终效果 + 学到什么

### 实测结果

| 场景 | 结果 |
|---|---|
| 按住 W 三秒 | 一直走，松开立刻停（最迟 16ms） |
| 点按 H/J/K | 每次只触发一次 |
| 按住 H 两秒 | 不会连续触发 |
| 摇杆斜向（W+A） | 右上 45°，方向向量叠加后归一化 |

日志现在每个键只有一对状态变化：

```
[keymap] poll down W
[keymap] poll up W
```

### 学到的

1. **Qt 的 `isAutoRepeat()` 在 Windows 上不可信**，不能作为去重依据
2. **Windows 的自动重复是 Press/Release 成对发**，不是只有 Press
3. **事件回调里读 `GetAsyncKeyState` 有滞后**，真松手那一刻可能还报按着
4. 结论：**游戏输入这种实时性要求高的场景，轮询硬件状态比订阅事件更可靠**——多 16ms 延迟，换来完全确定的行为

### 目前的限制

- 按键录制（现在要手打键名，如 `Q`、`Space`）
- 摇杆四向键只能在改键面板里改，新建摇杆固定 W/A/S/D
- 没有按游戏包名自动切换配置
- 编辑器不显示已有键位名称以外的信息（类型只能靠图标 ◎ 区分）
## 七、按键录制

编辑模式下**左键点一个圆点**（摇杆除外），顶部提示变成「请按下要绑定的键…」，按一下键盘就把那个键绑上，位置和类型都不变；改完自动退出录制状态。

### 为什么录制要放在叠加层

第一版把收键逻辑写在 `VideoItem::keyPressEvent` 里，点了圆点后 `record_index_` 确实设上了（日志有 `record start index 5`），但**按键永远收不到**。

原因：编辑模式下叠加层盖住整个画面，鼠标事件全被它接走，`VideoItem` 从头到尾没被点过，拿不到键盘焦点，`keyPressEvent` 根本不触发。在 `BeginKeyRecord()` 里调 `forceActiveFocus()` 也没用——紧接着的 MouseArea 点击又把焦点换走了。

改法是把“收键”交给本来就在最上层的叠加层：

```qml
// 录制时由叠加层接键盘：VideoItem 在编辑模式下拿不到焦点，只能在这里收键
focus: videoController.recording
Keys.onPressed:
{
    videoController.BindRecordedKey(event.key)
    event.accepted = true
}
```

后端只留一个直通方法 `BindRecordedKey(qt_key)`，`BeginKeyRecord` 负责置状态，QML 负责收键。

**QML 控件要不要自己收键盘，取决于它是不是“被点的那个东西”**——被点的不一定拿得到焦点，覆盖层和底层 item 的焦点归属必须分开看。

### 验证

```
[keymap] record start index 5
[keymap] record bound "Q" to index 5
[keymap] record start index 6
[keymap] record bound "C" to index 6
```

绑定后圆点文字立即更新，退出编辑模式时一并写回 JSON。
## 八、连点器（抢票用）

侧边栏一个按钮，只有开关两态：

```
连点 关  ⇄  连点 50
```

开启后**按住空格键**，在**鼠标所在位置**每 50ms 点一次，松开空格立即停止。

### 两个实现细节

**位置不靠悬停事件记，而是每次点击时现查全局光标。**

```cpp
// 位置直接查全局光标：不做 hover 跟踪，避免影响滚轮和拖动
const QPointF local = mapFromGlobal(QCursor::pos());
if (local.x() < 0 || local.y() < 0 || local.x() >= width() || local.y() >= height())
{
    return;                       // 鼠标不在画面上就不点
}
```

第一版注册了 `setAcceptHoverEvents(true)` 来记位置，结果**滚轮失效、拖动变快**——因为开了悬停事件后，滚轮和移动事件被当成 hover 吞掉了。改成现查光标就完全不动事件策略。

**触发判断同样是轮询**：每 10ms 查一次 `GetAsyncKeyState(VK_SPACE)`，和按键映射同一套思路，不受自动重复事件影响。

手指 id 用 99，和鼠标（0xFFFF…）、捏合（1、2）、键位映射（10+）都错开。
