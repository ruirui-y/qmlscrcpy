# 构建与测试

## 一、背景

每天干活都要碰这几件事：用的是哪套 Qt、配置/构建/测试三条命令怎么敲、跑之前要设哪些环境变量、哪些测试要真机、以及环境上撞过的坑。写下来免得每次重新翻聊天记录。

## 二、正文

### 装好这套环境

| 项 | 版本 |
|---|---|
| Qt | 6.8.3 msvc2022_64（`H:/Qt/6.8.3/msvc2022_64`） |

Qt5 那条 preset（`windows-*`）还留着，但渲染已经全部走 RHI + D3D12，只能挂在 Qt6 上，日常用 `qt6-*` 这组。

### 记住三条命令

```powershell
cd H:\YJJ\Project\QmlScrcpy

cmake --preset windows-debug                              # 配置
cmake --build --preset build-windows-debug                # 构建
ctest --test-dir build\windows-debug -C Debug --output-on-failure   # 测试
```

产物在 `build\qt6-debug\bin\Debug\QmlScrcpy.exe`。

### 跑起来看它连哪台设备

```powershell
# 把 adb 放进 程序目录\Tools\ 就会自动用它，否则走 PATH
$env:QS_DEVICE_SERIAL="192.168.31.115:5555"
$env:QS_LOG_LEVEL="info"                           # 每秒统计默认就开，无需额外设置
build\qt6-debug\bin\Debug\QmlScrcpy.exe
```

### 用环境变量调行为

| 变量 | 作用 |
|---|---|
| `QS_DEVICE_SERIAL` | 跑真机用例时的设备序列号 |
| `QS_DEVICE_SERIAL` | 自动连这台设备，省得点按钮 |
| `QS_SCRCPY_SERVER` | 指定 scrcpy-server 路径，默认用 `third_party/scrcpy-server` |
| `QS_TRACE_FRAMES` | `1` 时打印每帧明细（默认只有每秒统计） |
| `QS_GRAB` | 启动 6 秒后截图到这个路径并退出，用于无人值守核对画面 |
| `QS_FORWARD` | 测试里强制走 forward 隧道 |
| `QS_LOG_LEVEL` | 临时覆盖 config.ini 里的日志级别（debug/info/warning/critical） |

其它有用的 Qt 变量：

| 变量 | 作用 |
|---|---|
| `QSG_INFO=1` | 打印渲染器信息（渲染循环、后端、显卡） |
| `QSG_RENDERER_DEBUG=render` | 打印每帧渲染状态 |

### 撞过的环境坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 测试里堆损坏 `0xC0000374` | PATH 里第一个 Qt 和编译用的不是同一套 | 每个测试目标把 Qt DLL 拷到 exe 同目录（`qs_deploy_qt_runtime`） |
| `C1041 ... vc143.pdb` / `LNK1168` | 上一次的 exe 或 cl.exe 还活着 | 构建前先 `Stop-Process -Name QmlScrcpy` |
| 部署后没有 QML 模块 | 部署脚本没用 `--qmldir`，或 PATH 里的 windeployqt 不是同一套 | `cmake/DeployQt.cmake` 里把 Qt bin 放 PATH 最前面，并强制检查 `qml/*/qmldir` |
| QML 里 `Cannot assign to non-existent property "palette"` | `Window` 没有 palette（那是 Control 的属性） | 给每个控件单独配色，别在 Window 上设 |
| 读配置文件时 `QSettings::sync()` 卡几秒 | 每个尺寸变化事件都写盘 | 停在 400ms 后防抖写一次 |

### 写代码时的约定速查

- 大括号一律独占一行（`if` / lambda / namespace 都一样）
- 行尾注释对齐第 97 列；块注释只写一行，最多两行，ASCII 图例外
- 单行上限 120 列，能一行写完的绝不折行
- 每个 `.cpp` 函数头顶一行中文注释；构造函数/析构函数不加
