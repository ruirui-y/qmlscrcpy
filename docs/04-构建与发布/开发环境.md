# 开发环境踩坑记录

记录**不涉及代码本身、但会浪费大量时间**的环境问题。每一条都要求：现象、定位过程、结论、以后怎么办。

## 一、现象

用 VS 2022 的「打开文件夹」打开 QmlScrcpy，解决方案资源管理器里**所有文件的 Git 状态装饰（锁图标、忽略红圈）全部消失**，但：

- 菜单栏 Git 一切正常
- 「Git 更改」窗口正常显示分支 `master` 和改动文件
- 编辑器左侧的修改条正常

而且**不是稳定复现**：有时候有图标，有时候没有。

## 二、实录

### 先把无关的方向逐个排除

| 方向 | 怎么排除的 | 结论 |
|---|---|---|
| 仓库坏了 | `git status --porcelain` 0 条、142ms、无锁文件、能写 | 排除 |
| 仓库太大 | 清掉 `setup/stage`（1.2 GB）后仍复现 | 排除 |
| `.vs` 缓存 | 删过 `.vs`、删过 `.git/ms-persist.xml` | 排除 |
| Git 提供程序没启用 | 菜单、选项、Git 更改面板都正常 | 排除 |
| 改了文件也没标记 | 用户实测：改 README 后依旧无标记 | 排除“仓库干净”的解释 |
| 组件损坏 | `devenv /log` 取证：111 个包 Begin/End 全部成对 | **排除** |

### 冷启动抓一份 ActivityLog

关键一步是**用命令行冷启动抓 ActivityLog**：

```powershell
# 必须先关掉所有 VS（VS 是单实例，否则命令被转发、日志不落盘）
& "C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\IDE\devenv.exe" `
    /log "C:\Users\Mars\AppData\Local\Temp\vslog.xml" "H:\YJJ\Project\QmlScrcpy"
```

解析日志：

```powershell
[xml]$x = Get-Content $log -Encoding UTF8
$entries = $x.SelectNodes('//entry')
$entries | Where-Object { $_.description -match 'Git|Scc|Workspace' }
```

结果：

```
包加载：Begin 111 个 / End 111 个，全部成对
Git 相关：SccProviderPackage                 ✔ 正常加载
         SccProviderStubPackage             ✔ 正常加载
         Git Version Control_GitSccProvider ✔ 正常导出
错误：Extension Manager: Unable to load DLL 'PkgDefMgmt.dll'
      → 误报，文件其实在 Common7\IDE\PkgdefMgmt.dll（17.0.37708.7）
```

**结论：Git 提供程序加载成功，没有任何包失败。**

### 定位到冷启动时序竞态

```
启动 VS
  ├─ 并行加载 111 个功能包（含 Git 状态服务）
  └─ 命令行带了文件夹 → 立刻开始加载文件夹

加载文件夹时会"问一次"Git 状态：
    Git 服务：我还没初始化完
    文件夹：那就不画了
                ↓
        Git 服务初始化完成，但没人再问它
                ↓
        图标永久空白（重启文件夹才可能恢复）
```

### 摸清什么时候必现

| 路径 | 结果 |
|---|---|
| 任务栏跳转列表 / 命令行直接带文件夹冷启动 | ❌ 100% 无图标 |
| **先启动 VS 到开始页，再点文件夹** | ✅ 100% 有图标 |
| 用 `build\qt6-debug\QmlScrcpy.sln` | ✅ 100%（解决方案视图不走这条路径） |

这也解释了“有时有、有时没有”：磁盘快、扩展少时 Git 服务赶得上，反超就空白。

### 用桌面脚本先开 VS，再带文件夹打开

**桌面脚本** `用VS打开QmlScrcpy.cmd`：

```batch
@echo off
set DEVENV="C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\IDE\devenv.exe"
set FOLDER="H:\YJJ\Project\QmlScrcpy"

start "" %DEVENV%
timeout /t 8 /nobreak >nul
start "" %DEVENV% %FOLDER%
```

原理：第二次调用会**转发给已运行的实例**，此时 Git 服务早已就绪。机器慢就把 8 秒调到 12~15 秒。

### 试过但没用的修复

| 尝试 | 结果 |
|---|---|
| 升级 VS 2022 17.14.23 → 17.14.45 | 仍复现 |
| 删除 VS18 残留注册表键（`HKCU\...\VisualStudio\18.0/18.9`） | 只清掉跳转列表版本角标，不解决图标 |
| 重装/修复 VS | 未做——日志不支持“组件损坏”，做了也白做 |

## 三、结论

1. **“看起来别人记错了”时先别下结论**：用户说“有时有有时没有”，这就是竞态的信号，不是错觉
2. **ActivityLog 必须冷启动才抓得到**：VS 单实例会把命令转发给已运行实例，日志不落盘
3. **日志里 `Begin package load` 和 `End package load` 要成对检查**：这能直接判定“是加载失败还是加载成功但没人用”
4. **单条 Error 不代表根因**：`PkgDefMgmt.dll` 那条看着吓人，实际文件就在，属于启动早期路径未就绪

以后遇到同类问题：

```
图标/装饰消失，但功能正常
  → 先看是不是"冷启动带参数"
  → 先开主程序到主界面，再打开目标
  → 还不行再抓 ActivityLog
```
