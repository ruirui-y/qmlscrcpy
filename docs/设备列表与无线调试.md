# 设备列表与无线调试

控制窗第二张卡片：左边是在线设备下拉框，右边是「切无线」。

## 在线设备列表

```
adbd 里 adb devices 的输出
   ├── 过滤掉 state != "device" 的行（offline / unauthorized 都不要）
   ├── 存进 DeviceController::devices_
   └── 通过 Q_PROPERTY(QStringList devices) 给 QML 的 ComboBox 当 model
```

选中一台只做一件事：**把串号填进上面的输入框**。连接仍然由「连接」按钮触发——避免"点一下就偷偷连上"这种不可控行为。

刷新时机：点「刷新」、切完无线、启动时各刷一次。

## 无线调试怎么开

```
前提：先用数据线连着（adbd 必须在 USB 上活着）
        │
   ① Disconnect()        ← 先自己断开
        │
   ② adb tcpip 5555      ← 让设备的 adbd 在 5555 上再开一个监听
        │
   ③ 轮询 adb shell ip route，直到问出 "src 192.168.x.x"
        │
   ④ adb connect 192.168.x.x:5555（失败重试 3 次）
        │
   ⑤ 把 IP:5555 填进输入框，提示"可以拔线了，点连接"
```

### 为什么第一步要先自己断开

`adb tcpip 5555` 会**重启设备上的 adbd**。当前那条 USB 连接会立刻被对端关掉，视频线程会看到 `The remote host closed the connection`，界面上就会出现一句"视频出错"——明明是我们主动做的操作，看起来却像故障。

先 `Disconnect()` 把会话、解码器、读线程都收干净，然后再切，界面上就只会看到正常的"正在切无线调试 …"。

### 为什么只认 wlan0（踩过）

设备上 `ip route` 的输出**不一定只有 wifi**：

```
10.33.61.128/27 dev rmnet_data3 proto kernel scope link src 10.33.61.144   ← 移动网络在前
192.168.31.0/24  dev wlan0      proto kernel scope link src 192.168.31.114 ← wifi 在后
```

第一版取"第一个 src"，拿到的是 `10.33.61.144`（蜂窝网络），电脑根本连不上，界面报
`adb connect 10.33.61.144:5555 失败`。

现在只认含 `wlan` 的那一行；路由表里没有时再兜底查 `ip -f inet addr show wlan0` 的 `inet` 行。

### 为什么整个过程必须放工作线程

```
adb tcpip            ≤10s
轮询问 IP             8 × (500ms 睡眠 + ≤5s adb)
adb connect 重试      3 × ≤8s
────────────────────────────────
最坏情况 40 秒以上
```

第一版全跑在 GUI 线程上，点一下窗口就"未响应"。现在 `EnableWifi()` 只做两件快事（断开当前会话、置忙标志），剩下全丢给 `QThread::create(...)`，结果用 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 回主线程刷新状态。

### 为什么要轮询问 IP

adbd 重启需要一两秒，这期间 `adb shell` 会失败或者返回空。只问一次大概率拿到空字符串，所以每 500ms 问一次，最多 8 次：

```cpp
for (int attempt = 0; attempt < 8 && address.isEmpty(); ++attempt)
{
    QThread::msleep(500);
    const qsc::adb::AdbResult route = qsc::adb::Run(
        qsc::adb::AdbArgs::Shell(serial, QStringList() << "ip" << "route"), 5000);
    address = ParseWifiAddress(QString::fromUtf8(route.std_out_));
}
```

`ip route` 的输出形如：

```
192.168.31.0/24 dev wlan0 proto kernel scope link src 192.168.31.115
```

找 `src` 后面那个 token 就是设备地址。

### 为什么要重试 adb connect

adbd 刚重启时，偶尔会先拒一次连接。所以：

```cpp
connected = result.Ok() && !output.contains("failed");
```

注意 `adb connect` 失败时**退出码也可能是 0**，必须看输出里有没有 `failed`。

## 界面

```
┌─────────────────────────────────────────────┐
│ [e77121ed            ▼]        [ 切无线 ]   │
└─────────────────────────────────────────────┘
```

- 没有在线设备时下拉框显示"没有在线设备"（灰字）
- 切无线成功后输入框里变成 `192.168.31.115:5555`，同时写进 `window.ini` 的 `last_serial`（点连接成功之后）

## 常见问题

| 现象 | 原因 |
|---|---|
| `切无线失败：no devices/emulators found` | 线没连好，或者 adb 里这台设备 offline |
| `无线已开，但没问到设备 IP` | 设备没连 wifi，或者 `ip route` 被系统权限挡了；手动填 `<IP>:5555` |
| `adb connect ... failed` | 电脑和设备不在同一个网段，或者设备换了 IP |
| 切完无线后视频黑屏 | 正常——会话被主动断了，点「连接」重连 `IP:5555` |
