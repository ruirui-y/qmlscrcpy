# 自动更新（一键下载 + 静默安装）

客户端发现新版本后，不再只是"给个链接让你自己点"，而是能**下载 → 校验 → 静默安装 → 自动重启**。

## 1. 一次更新的完整流程

```
点「立即更新」
      │
      ▼
curl -L --fail -o %TEMP%\QmlScrcpy\QmlScrcpy_Setup_0.1.7.exe     ← 进度条按文件大小算
      │
      ├─ 失败/取消 → 删掉半截文件，状态栏说明原因
      ▼
核对 size（字节数必须完全一致）
      │
      ▼
算 SHA-256（放后台线程，45MB 约 200ms）
      │
      ├─ 不一致 → 删掉安装包，提示"校验失败"
      ▼
Setup.exe /SILENT /CLOSEAPPLICATIONS /NORESTART
      │
      ▼
自己 quit()，让安装程序覆盖正在运行的 exe
      │
      ▼
Inno 的 [Run] 段装完自动启动新版本
```

## 2. latest.json 多了两个字段

```json
{
  "latest": "0.1.7",
  "minimum": "0.1.0",
  "url": "https://gitee.com/bai-maxifeng/qmlscrcpy/releases",
  "notes": "这次改了什么",
  "published_at": "2026-11-13",
  "size": 47979834,
  "sha256": "9bf79e84…aac3"
}
```

| 字段 | 作用 | 缺了会怎样 |
|---|---|---|
| `size` | 判断下载是否完整 | 跳过完整性检查，只算哈希 |
| `sha256` | 判断安装包有没有被替换/损坏 | **不能自动更新**，按钮退回"去下载"（开浏览器） |

发版脚本 `setup/release_gitee.ps1` 会自动算这两个值，不用手填。

## 3. 为什么下载用 curl 而不是 Qt 网络

Qt 5.15 的 HTTPS 依赖 OpenSSL，而这套 Qt 安装里没有 `libssl-1_1-x64.dll`。要支持自动下载有两条路：

1. 把 OpenSSL DLL 打进安装包（+5MB，还要管许可证）
2. 用系统自带的 `curl.exe`（Win10 1803+ 就有，走 SChannel）

选了 2，和版本检查用的是同一套思路。命令就是：

```
curl.exe -L --fail --silent --show-error -o <目标> <链接>
```

- `-L` 跟随跳转（Gitee 的下载链接会 302 到 CDN）
- `--fail` 让 4xx/5xx 变成非 0 退出码，不然会把错误页当 exe 存下来

## 4. 进度为什么不解析 curl 的输出

`curl --progress-bar` 往 **stderr** 写，还带 `\r` 回退刷新，解析起来很脏。改成**轮询文件大小**：

```cpp
progressTimer->setInterval(300);          // 每 300ms 取一次 QFileInfo(path).size()
progress = received / expected;           // expected 来自 latest.json 的 size
```

简单、稳，300ms 的刷新率对进度条完全够。

## 5. 为什么要校验 SHA-256

下载路径上有三个不可信环节：

| 环节 | 可能的坏事 |
|---|---|
| DNS / 中间人 | 把 exe 换成木马 |
| CDN 缓存 | 拿到别的版本 |
| 网络中断 | 文件截断，安装到一半失败 |

只比 size 挡得住截断，挡不住替换，所以必须算哈希。`latest.json` 本身也就几十行 JSON，被篡改的影响面小得多。

哈希不能在主线程算（45MB 一遍约 200ms，进度条会卡），所以丢 `TaskRunner`：

```cpp
qsc::base::TaskRunner::Instance().Post([this, path, expect]() { /* QCryptographicHash */ });
```

## 6. 为什么安装包一定会弹 UAC

`setup\QmlScrcpy.iss` 里：

```ini
PrivilegesRequired=admin
DefaultDirName=D:\QmlScrcpy
```

装到 `D:\` 需要管理员权限，所以 `Setup.exe /SILENT` **仍然会弹 UAC**，用户要点一次"是"。这一步绕不过去——能绕过就是提权漏洞。

真要做到"完全无感"，得改成：

```ini
PrivilegesRequired=lowest
DefaultDirName={localappdata}\QmlScrcpy
```

代价是安装位置变化，老用户从 `D:\QmlScrcpy` 迁移（配置、日志、截图路径都要跟着动）。所以没做，保持现状。

## 7. /CLOSEAPPLICATIONS 是必须的

安装程序要覆盖 `QmlScrcpy.exe`，但 Windows 不允许覆盖正在运行的 exe。所以：

```cpp
QProcess::startDetached(setup, {"/SILENT", "/CLOSEAPPLICATIONS", "/NORESTART"});
QCoreApplication::quit();                    // 自己先退
```

`/CLOSEAPPLICATIONS` 让 Inno 主动给我们的进程发关闭消息；我们自己 `quit()` 更快。少了这一步，安装会卡在"请关闭 QmlScrcpy"。

## 8. 失败与退路

| 情况 | 表现 |
|---|---|
| 没连上网 / Gitee 不通 | 状态栏"下载失败（curl 退出码 6）" |
| 下载中途关程序 | 半截文件在 `%TEMP%\QmlScrcpy\`，下次下载前会先删 |
| 哈希不匹配 | 删掉安装包，提示"校验失败，已删除安装包" |
| latest.json 没给 sha256 | 按钮显示"去下载"，直接开浏览器（不会瞎装） |
| 安装程序起不来 | 提示"启动安装程序失败，去下载页手动安装" |

**永远保留"下载页"和"稍后"两个按钮**：自动更新失败时用户还能自己动手，而不是卡在一个不动的进度条上。

界面上的「立即更新 → 进度 → 安装 → 重启」需要人工验（涉及 UAC 和进程重启，自动化模拟不可靠）。

## 10. 已知限制

- **安装时必弹 UAC**（`PrivilegesRequired=admin`），不是完全静默
- 安全软件可能对"程序自己下载并执行 exe"报警，这是这一类功能的通病
- 不支持断点续传：中断就是重下
- 只校验 Gitee 那个直链，换源需要同时换 `url` 和 `sha256`
