# 启动自动连接

程序启动时自动连上一次用过的设备，省得每次手动点。**只做一次**：用户之后主动断开，不会再自动连。

## 规则

```
启动 → adb devices 拿在线列表
        │
        ├─ 上次连过的设备在列表里  → 连它
        ├─ 否则 QS_DEVICE_SERIAL 在列表里 → 连它（调试用）
        └─ 都不在 → 什么都不做，停在未连接状态
```

关键点：**候选串号必须在在线列表里才连**。不然会白等一次 1.5 秒的失败连接，还会在状态栏留一句莫名其妙的报错。

```
上次连的是 e77121ed（有线）
这次开机只插着 wifi，在线列表里只有 192.168.31.115:5555
   → 不在列表里，不自动连
   → 用户点「连接」时用的是输入框里的 proposedSerial（第一台在线设备）
```

## 上次连的设备记在哪

`window.ini`：

```ini
[device]
last_serial=e77121ed
```

写入时机：`ApplyConnected()` 成功之后。所以**只有连成功过才会被记住**，失败不会污染这个值。

为什么放 `window.ini` 而不是 `config.ini`：`config.ini` 是我们只读、用户手改的文件（带注释），程序往里写会被 `QSettings` 把注释转义掉。`window.ini` 本来就是程序自己写的。

## 代码

```cpp
// src/main.cpp
controller.RefreshDevices();
const QString fallback = QString::fromLocal8Bit(qgetenv("QS_DEVICE_SERIAL"));
const QString auto_serial = controller.PickStartupSerial(fallback);
if (!auto_serial.isEmpty())
{
    qInfo() << "[app] 自动连接上次的设备" << auto_serial;
    controller.Connect(auto_serial);
}
```

```cpp
// src/device_controller.cpp
QString DeviceController::PickStartupSerial(const QString &fallback) const
{
    AppSettings settings;
    const QString last = settings.LastSerial();
    if (!last.isEmpty() && online_serials_.contains(last))
    {
        return last;
    }
    if (!fallback.isEmpty() && online_serials_.contains(fallback))
    {
        return fallback;
    }
    return QString();
}
```

`online_serials_` 是 `RefreshDevices()` 里存下来的在线设备列表，所以 `PickStartupSerial()` 必须在刷新之后调。

## 为什么不用 QS_DEVICE_SERIAL 优先

调试时它是"我想连这台"，日常使用时"上次那台"更贴近真实意图。所以优先级是：

```
window.ini 的 last_serial  >  QS_DEVICE_SERIAL  >  不连
```

两个都在列表里才连；都没设就干干净净停在未连接状态，等用户自己点。

## 验证

启动日志会出现：

```
[app] 自动连接上次的设备 "e77121ed"
[session] 开始连接 "e77121ed"
[session] 连接完成： "RMX5010" QSize(1264, 2776) reverse 耗时 1200 ms
```

`window.ini` 里 `last_serial` 会随每次成功连接更新。
