# 双仓库发版（GitHub + Gitee）

代码在 GitHub，安装包在 Gitee。这篇写清楚**每次发版到底要做哪几步**，以及为什么这么分工。

## 1. 为什么要两个仓库

| 东西 | 放哪 | 原因 |
|---|---|---|
| 代码、issue、PR | GitHub | 生态好，找代码的人在这里 |
| 安装包（exe） | **Gitee** | GitHub Releases 国内下载经常连不上，45MB 要等很久 |
| `latest.json` | 两个都放 | 客户端的检查更新走 Gitee（国内快），GitHub 那份当备份 |
| 发布说明 | 两边都要 | Gitee 是主发布页，GitHub 只留文字不留 exe |

## 2. 一次性准备（只做一次）

```powershell
cd H:\YJJ\Project\QmlScrcpy

# ① 加两个远程：gitee 单推，all 双推
git remote add gitee https://gitee.com/bai-maxifeng/qmlscrcpy.git
git remote add all https://github.com/ruirui-y/qmlscrcpy.git
git remote set-url --add --push all https://gitee.com/bai-maxifeng/qmlscrcpy.git
git remote set-url --add --push all https://github.com/ruirui-y/qmlscrcpy.git

# ② 确认 all 有两个 push 地址（必须两行 push）
git remote -v | Select-String '^all'
```

正确结果一定是这样，**少了 GitHub 那行就只会推 Gitee**：

```
all	https://github.com/ruirui-y/qmlscrcpy.git (fetch)
all	https://gitee.com/bai-maxifeng/qmlscrcpy.git (push)
all	https://github.com/ruirui-y/qmlscrcpy.git (push)
```

```powershell
# ③ Gitee 令牌（只放本地，.refs/ 已被 gitignore）
Set-Content -Path .refs\gitee_token.txt -Value '你的私人令牌'
$env:GITEE_TOKEN = (Get-Content -Raw -Encoding UTF8 .refs\gitee_token.txt).Trim()
```

## 3. 每次发版（六步）

```powershell
# ① 改版本号（两处）
#    CMakeLists.txt        project(QmlScrcpy VERSION 0.1.7 ...)
#    setup\QmlScrcpy.iss   #define MyAppVersion "0.1.7"

# ② 打包
powershell -ExecutionPolicy Bypass -File setup\collect.ps1
setup\build_installer.bat

# ③ 提交 + 打 tag + 双推
git add -A
git commit -m "chore(release): 版本号升到 0.1.7"
git tag -a v0.1.7 -m "QmlScrcpy 0.1.7"
git push all master
git push all v0.1.7

# ④ Gitee 建发行版 + 传 exe + 改 latest.json
$env:GITEE_TOKEN = (Get-Content -Raw -Encoding UTF8 .refs\gitee_token.txt).Trim()
powershell -ExecutionPolicy Bypass -File setup\release_gitee.ps1 -Version 0.1.7

# ⑤ 提交 latest.json 再双推
git add latest.json
git commit -m "chore(release): latest.json 指向 0.1.7"
git push all master

# ⑥ GitHub 只发说明，不传 exe
gh release create v0.1.7 --title "QmlScrcpy 0.1.7" --notes-file docs\release-notes\v0.1.7.md
```

## 4. 发完之后必须核对

```powershell
"GitHub: $(git ls-remote origin master)"
"Gitee : $(git ls-remote gitee master)"
```

两行 hash **一样**才算双推成功。踩过一次：`all` 的 push 地址只配了 Gitee，`git push all` 的退出码还是 0，看起来一切正常，实际 GitHub 停在旧提交上。

## 5. 客户端更新链路的自检

```powershell
# 客户端实际会请求的地址（?v= 按小时变）
curl.exe -sL "https://gitee.com/bai-maxifeng/qmlscrcpy/raw/master/latest.json?v=1"

# 安装包能不能下
curl.exe -sL -o NUL -w "%{http_code} %{size_download}`n" `
  "https://gitee.com/bai-maxifeng/qmlscrcpy/releases/download/v0.1.7/QmlScrcpy_Setup_0.1.7.exe"
```

期望：JSON 里 `latest` 是新版本号，exe 返回 `200` 且字节数对得上（≈45.8MB，即 4.7e7 左右）。

## 6. 踩过的坑（都跟编码有关）

| 坑 | 现象 | 原因与解法 |
|---|---|---|
| `Get-Content -Raw` 读中文 | 写出去的正文全是乱码（`锟斤拷`） | **PS 5.1 默认按 ANSI/GBK 解码**，必须加 `-Encoding UTF8` |
| `Set-Content -Encoding UTF8` 写 JSON | 带 BOM，客户端 JSON 解析失败 | 用 `[IO.File]::WriteAllText(path, text, UTF8Encoding($false))` |
| PowerShell 发中文 JSON 给接口 | `400 Bad Request` | 改 `curl --data-binary @文件`（UTF-8 无 BOM） |
| `git push all master` 只推了一个 | 另一端停在旧提交 | 检查 `git remote -v` 里 `all` 是否有两条 `(push)` |

## 7. 一句话版

```
改版本号 → 打包 → commit+tag → push all
→ release_gitee.ps1（建发行版+传exe+改latest.json）
→ commit latest.json → push all
→ gh release create（只写说明）
→ 核对两端 hash 一致
```
