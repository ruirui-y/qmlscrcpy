# 渲染后端从 FBO + OpenGL 换到 RHI + D3D12

## 一、背景

零拷贝在 D3D11 上撞了三次墙（见 [零拷贝为什么失败](../经验知识/零拷贝为什么失败.md)）。
根因不是代码写错，是 D3D11 的模型：一个设备只有一条即时上下文，
`VideoProcessorBlt` 一绑 RTV 就把 Pass 级状态改了，Qt RHI 的缓存还以为自己是对的，
后面几十个 draw 全用错状态，最后 `Device loss detected in Present()`。

要根治只能换 API：状态烘进 pipeline、命令列表归自己。D3D12 是这个形状，
Vulkan 也是，但 Windows 上 D3D12 跟 Qt 的后端是同一套，省事。

另一件事：FFmpeg 6.1.3 没有 d3d12va。

## 二、计划

分三步，一次只换一个变量：

```
1. 升 FFmpeg 到带 d3d12va 的版本
2. 只换渲染后端（OpenGL → D3D12），解码仍走 d3d11va 读回
   画面能出就说明后端没问题
3. 删掉 GL 那套，只留一条路
```

验证标准：每步编译通过 + 能出完整画面 + 日志里后端名字对。

## 三、实录

### 1. 升 FFmpeg：计划 7.1，实际装了 8.1

原计划装 FFmpeg 7.1（BtbN 构建带 d3d12va）。下载时 7.1 的资产已经下架，只剩 8.1 / 9.0 / master。

选 8.1：稳定线，签名档里 d3d12va / vulkan / d3d11va 都在，
LGPL 版本存在（跟原来的 6.1.3 lgpl-shared 许可一致，发版不用改 GPL）。

```bash
ffmpeg -hide_banner -hwaccels
→ cuda / vaapi / dxva2 / qsv / d3d11va / opencl / vulkan / d3d12va / amf
```

DLL 从 `avcodec-60` 跳到 `avcodec-62`。6→8 的 API 变化没影响我们：
只用 `avcodec_send_packet` / `avcodec_receive_frame` / `av_hwdevice_ctx_*` / `av_frame_*`，签名没变。

### 2. 换基类：createRenderer 不能是 const

```
error C3668: "VideoItem::createRenderer": 包含重写说明符"override"的方法没有重写任何基类方法
```

Qt 6.8 的声明是非 const：

```cpp
virtual QQuickRhiItemRenderer *createRenderer() = 0;
```

Qt5 的 `QQuickFramebufferObject::createRenderer() const` 是 const，照抄编不过。

### 3. 找不到 rhi/qrhi.h

```
error C1083: 无法打开包括文件: "rhi/qrhi.h"
```

`include/QtGui/rhi/` 这个目录根本不存在，只有私有头：

```
H:\Qt\6.8.3\msvc2022_64\include\QtGui\6.8.3\QtGui\private\qrhi_p.h
```

解决：链接 `Qt6::GuiPrivate`，include 写 `<QtGui/private/qrhi_p.h>`。

### 4. 第一次跑：对角线黑块

一半是视频，一半是斜切的黑三角。

`QRhiGraphicsPipeline` 默认拓扑是 `Triangles`，4 个顶点只组一个三角，剩下半个屏幕没画。

```cpp
pipeline_->setTopology(QRhiGraphicsPipeline::TriangleStrip);
```

### 5. 第二次跑：Qt 断言崩溃

我一度以为 Qt 会替我们开 render pass，把 `beginPass` / `endPass` 删了，于是：

```
ASSERT: "cbD->recordingPass == QD3D11CommandBuffer::RenderPass"
         in file C:\Users\qt\work\qt\qtbase\src\gui\rhi\qrhid3d12.cpp, line 892
```

`render()` 里必须自己 `beginPass` / `endPass`，Qt 只负责把 `QRhiCommandBuffer` 递给你。

### 6. initialize 被调了 567 次

```
[rhi] 后端 D3D12 initialize 第 567 次
```

16 秒里调了 567 次 —— Qt 会重复调 `initialize()`，我们每次都新建采样器和顶点缓冲，全泄漏。

```cpp
// 成员判空直接 return，只做一次
if (rhi_ != nullptr && sampler_ != nullptr && vertex_buffer_ != nullptr)
{
    return;
}
```

改完 16 秒内只调 1 次。

### 7. 删 GL

```
git rm ui/video_renderer.cpp   599 行
git rm ui/video_renderer.h      96 行
git rm ui/video_frame_source.h  44 行
```

CMake 去掉 `OpenGL` 组件和 `Qt6::OpenGL`，`video_item.cpp` 去掉 4 个 `QOpenGL*` 头。
现在全仓库没有一行 OpenGL 调用。

### 8. 顺手拆两坨

埋点和输入都堆在 `video_item.h` 里，改渲染要动画布头文件。趁这次拆开：

| 新文件 | 内容 | 结果 |
|---|---|---|
| `ui/frame_probe.{h,cpp}` | FrameTrace、帧序号、分档、每秒统计、逐帧打印 | `video_item.h` 215 → 153 行 |
| `ui/video_input.{h,cpp}` | 鼠标/滚轮/键盘/捏合/键位映射/连点器 | `video_item.h` 153 → 139 行 |

拆 `VideoInput` 时踩了三个：

```
① 事件体搬走后调 QQuickRhiItem::mousePressEvent 报 protected 不可访问
   → 画布加 6 个 Base* 公开转发，VideoInput 通过 owner_ 回调
② 匿名 namespace 的辅助函数（ActionCode / KeyName / ModifierDownNow / kClickerPointerId）
   原来两个 TU 各留一份，搬的时候漏了一份 → 链接期才暴露
③ 定时器成员被连带删掉 → 构造函数编不过，补回 5 个
```

## 四、留的坑

上屏 64~67 fps（GL 时代 100~120）。

「到达 120 / 上屏 67」说明解码端能跑满，是交换链节拍限制（vsync 或渲染循环节奏）。
等零拷贝做完再统一量，现在的数不代表最终形态。
