# D3D12 迁移：从 FBO + OpenGL 全面换到 RHI + D3D12

这一阶段把渲染后端从 **Qt5 时代的 FBO + OpenGL** 换成 **Qt6 的 QQuickRhiItem + D3D12**，
然后借着这次改动把混在一起的头文件拆开。

起因是这样的：零拷贝在 D3D11 上撞了三次墙（见 [零拷贝为什么失败](../经验知识/零拷贝为什么失败.md)），
根因是 D3D11 只有一条即时上下文，`VideoProcessorBlt` 一动状态就把 Qt RHI 的账本搞崩。
要根治，就得换一个「状态烘进 pipeline、命令列表归自己」的 API —— 也就是 D3D12。

---

## 一、这一阶段要做什么

### 目标

```
① 渲染后端：OpenGL(FBO) → D3D12(RHI)
② 删掉所有 OpenGL 代码，只留一条渲染路径
③ 顺手拆掉混在一个头文件里的输入与埋点
```

### 范围

```
做：
  - FFmpeg 升级（6.1.3 → 8.1，要 d3d12va）
  - VideoItem 基类换成 QQuickRhiItem
  - 新写 RHI 渲染器（两平面上传 + NV12 着色器）
  - 删掉 GL 渲染器与 OpenGL 依赖
  - 埋点抽成 FrameProbe，输入抽成 VideoInput

不做：
  - 解码器还没换 d3d12va（下一阶段）
  - 零拷贝还没做（再下一阶段）
  - 这阶段只保证「读回内存 + RHI 绘制」能跑
```

### 为什么分这么细

```
一次换掉「后端 + 解码 + 零拷贝」三件事，出问题根本分不清是谁的锅。
所以先只换后端，解码仍走 d3d11va 读回，画面能出就说明后端没问题。
```

## 二、怎么做的

### 2.1 FFmpeg 升级：为什么是 8.1 不是 7.1

```
原本计划：FFmpeg 7.1（BtbN 构建带 d3d12va）
实际探测：7.1 的资产已经下架（HTTP 404）
可选：8.1 / 9.0 / master

选 8.1 的理由：
  稳定线（不是 nightly）
  签名档里 d3d12va / vulkan / d3d11va 全在
  LGPL 版本存在（和原来的 6.1.3 lgpl-shared 许可一致，发行时不用改 GPL）
```

验证：

```
ffmpeg.exe -hide_banner -hwaccels
→ cuda / vaapi / dxva2 / qsv / d3d11va / opencl / vulkan / d3d12va / amf
```

DLL 版本从 `avcodec-60` 跳到 `avcodec-62`，但 6→8 的 API 变化**没影响我们的解码代码**
（只用 `avcodec_send_packet` / `receive_frame` / `hwdevice_ctx_*` / `av_frame_*`，签名没变）。

### 2.2 渲染后端切换

```cpp
// src/main.cpp
QQuickWindow::setGraphicsApi(QSGRendererInterface::Direct3D12);   // 原来：OpenGL
```

```cpp
// ui/video_item.h
class VideoItem : public QQuickRhiItem          // 原来：QQuickFramebufferObject
{
    QQuickRhiItemRenderer *createRenderer() override;
};
```

### 2.3 RHI 渲染器（新文件，228 行）

只保留一条路：**CPU 读回 → 两张平面纹理 → 着色器转色 → 画一个矩形。**

```
synchronize（GUI 线程，没有 GPU 上下文）
    把 Frame 的 Y/UV 紧凑拷进 plane_y_ / plane_uv_

render（渲染线程）
    ① uploadTexture(texture_y_)      R8
    ② uploadTexture(texture_uv_)     RG8
    ③ beginPass → setGraphicsPipeline → setShaderResources
       → setVertexInput → draw(4) → endPass
```

着色器用 QSB（构建时把 `ui/shaders/*.qsb` 拷到 exe 同级 `shaders/`）：

```glsl
// nv12.frag：BT.601 有限范围，和 GL 版同一套系数
float y = texture(texY, v_uv).r - 0.0625;
float u = texture(texUV, v_uv).r - 0.5;
float v = texture(texUV, v_uv).g - 0.5;
```

### 2.4 删掉的东西

| 文件 | 行数 | 说明 |
|---|---|---|
| `ui/video_renderer.cpp` | 599 | FBO + GL 渲染器，含 wglDX interop 实验代码 |
| `ui/video_renderer.h` | 96 | 同上 |
| `ui/video_frame_source.h` | 44 | exp 分支带过来的接口，改直连后没用上 |

依赖：

```
CMakeLists.txt        find_package 去掉 OpenGL 组件
src/CMakeLists.txt    去掉 Qt6::OpenGL 链接
ui/video_item.cpp     去掉 4 个 QOpenGL* 头
```

**现在全仓库没有一行 OpenGL 调用。**

## 三、写完为什么不是理想效果（踩的 5 个坑）

### 坑 1：`createRenderer()` 不能是 const

```
error C3668: "VideoItem::createRenderer": 包含重写说明符"override"的方法没有重写任何基类方法
```

Qt 6.8 的声明是：

```cpp
virtual QQuickRhiItemRenderer *createRenderer() = 0;      // 注意：非 const
```

Qt5 的 `QQuickFramebufferObject::createRenderer() const` 是 const，照抄就编译不过。

### 坑 2：Qt 6.8 没有公开的 `rhi/qrhi.h`

```
error C1083: 无法打开包括文件: "rhi/qrhi.h"
```

实际位置：

```
H:\Qt\6.8.3\msvc2022_64\include\QtGui\6.8.3\QtGui\private\qrhi_p.h
```

解决：

```cmake
target_link_libraries(... Qt6::GuiPrivate)     # QQuickRhiItem 的 QRhi 类型在私有头里
```

```cpp
#include <QtGui/private/qrhi_p.h>
```

### 坑 3：4 个顶点只画出 1 个三角形（对角线黑块）

现象：屏幕上一半是视频，一半是斜切的黑三角。

原因：`QRhiGraphicsPipeline` 默认拓扑是 `Triangles`，4 个顶点只组一个三角。

```cpp
// 改后
pipeline_->setTopology(QRhiGraphicsPipeline::TriangleStrip);
```

### 坑 4：`render()` 里必须自己 `beginPass`（我判断错了一次）

我一度以为「Qt 会替你开 pass」，于是删掉了 `beginPass/endPass`，结果：

```
ASSERT: "cbD->recordingPass == QD3D11CommandBuffer::RenderPass"
         in file ...\qrhid3d12.cpp, line 892
```

结论：**`QQuickRhiItemRenderer::render()` 里必须自己 beginPass/endPass**，
Qt 只负责把 `QRhiCommandBuffer` 递给你。

### 坑 5：`initialize()` 被调用了 567 次

日志：

```
[rhi] 后端 D3D12 initialize 第 567 次
```

Qt 会重复调 `initialize()`，我们每次都在里面新建采样器 + 顶点缓冲 —— **泄漏**。

```cpp
// 改后：幂等守卫
if (rhi_ != nullptr && sampler_ != nullptr && vertex_buffer_ != nullptr)
{
    return;
}
```

改完：16 秒内只调 **1 次**。

## 四、怎么定位的

| 现象 | 定位手段 | 结论 |
|---|---|---|
| 编译不过（C3668） | 直接读 Qt 头文件 `qquickrhiitem.h` | `createRenderer()` 非 const |
| 编译不过（C1083） | 在 Qt include 目录递归找 `qrhi_p.h` | 只有 private 版本，要 GuiPrivate |
| 对角线黑块 | 截图 + 想起 GL 版的 `GL_TRIANGLE_STRIP` | 缺 `setTopology` |
| 断言崩溃 | 弹窗给出文件行号 `qrhid3d12.cpp:892` | Qt 要求调用方开 pass |
| `initialize` 567 次 | 在构造/析构/initialize 各加一行计数日志 | Qt 重复调用，需幂等 |

**教训**：这五个坑全是「Qt 的行为和我以为的不一样」，
最快的定位方式不是猜，是**读 Qt 头文件 + 加计数日志**。

## 五、怎么解决的（外加代码拆分）

### 渲染相关的改动

| 文件 | 动作 |
|---|---|
| `src/main.cpp` | `setGraphicsApi(Direct3D12)` |
| `ui/video_item.{h,cpp}` | 基类换 `QQuickRhiItem`；`componentComplete` 调基类 |
| `ui/video_rhi_renderer.{h,cpp}` | 新建，两平面 + NV12 着色器 + 三角带 |
| `src/CMakeLists.txt` | 登记新文件、`Qt6::GuiPrivate`、shaders 拷贝命令 |

### 顺手做的代码拆分

因为埋点和输入都堆在 `video_item.h` 里，改一次渲染要动画布头文件，所以一起拆了：

| 新文件 | 内容 | 结果 |
|---|---|---|
| `ui/frame_probe.{h,cpp}` | FrameTrace、帧序号、分档计数、每秒统计、逐帧打印 | `video_item.h` 215 → 153 行 |
| `ui/video_input.{h,cpp}` | 鼠标/滚轮/键盘/捏合/键位映射/连点器 | `video_item.h` 153 → **139 行** |

画布里只剩转发，用折叠区隔开：

```cpp
#pragma region input // 输入：全部转发到 VideoInput，别在这里加逻辑
    void SetWheelMode(const QString &mode) { input_->SetWheelMode(mode); }
    ...
#pragma endregion
```

拆 `VideoInput` 时踩的三个坑：

```
① 事件体搬走后调 QQuickRhiItem::mousePressEvent 报 protected 不可访问
   → 在 VideoItem 上加 6 个 Base* 公开转发，VideoInput 通过 owner_ 回调

② 匿名 namespace 里的辅助函数（ActionCode / KeyName / ModifierDownNow / kClickerPointerId）
   原来两个 TU 各留一份，搬的时候漏了一份 → 链接期才暴露

③ 定时器成员被连带删掉 → 构造函数编译不过，补回 5 个
```

## 六、最终效果 + 学到什么

### 实测

```
[rhi] 后端 D3D12
[rhi] 渲染目标尺寸 QSize(412, 908)          ← 只建一次，没有每帧重建
[perf] 1s 到达 84~120 帧，上屏 64~67 帧，丢 0~1
[perf] 帧 972 上屏：synchronize 1.119 ms，绘制 2.439 ms，提交 1.259 ms
```

| 指标 | 数值 |
|---|---|
| 编译 | 0 错误 |
| 断言 / 崩溃 | 0 |
| `initialize` 调用 | 1 次（修复前 567 次） |
| 画面 | 完整，无黑块 |
| 代码净变化 | 删 739 行 GL，加 228 行 RHI |

### 一个还没解释的差异

| 路径 | 上屏帧率 |
|---|---|
| master（FBO + GL） | 100~120 |
| RHI + D3D12 | 64~67 |

「到达 120 / 上屏 67」说明解码端能跑满，是交换链节拍限制（vsync 或渲染循环节奏）。
这条先记着，等零拷贝做完再统一量，现在测的 67fps 不代表最终形态。

### 学到什么

1. **Qt5 到 Qt6 的渲染器不是「改个基类」**：`createRenderer` 签名、上下文获取方式、
   pass 归属、纹理上传时机全变了，逐个踩。
2. **私有头文件是可以用，但要显式链接 `Qt6::GuiPrivate`**，而且升级 Qt 时要复查。
3. **`initialize()` 不一定只调一次**，资源创建要幂等 —— 这类「框架不承诺」的行为必须加计数日志验证。
4. **删旧代码比留旧代码省心**：GL 那套留着只会让人以为还有两条路。
5. **一次只换一个变量**：后端、解码、零拷贝分三步走，出问题才能定位到具体哪一步。
