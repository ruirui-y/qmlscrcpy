# 日志与配置

## 文件位置

配置文件统一在 exe 下的 `config/` 目录，日志和截图各自独立；绿色软件，拷走整目录就能用：

```
bin/Debug/
├── config/
│   ├── config.ini      用户手改：日志级别、采集参数、滚轮默认值
│   └── window.ini      程序自己写：窗口位置尺寸、上次设备、命令行开关
├── Log/
│   ├── LOG_2026_11_12.log    今天的日志，按天一个文件
│   ├── LOG_2026_11_11.log
│   └── ...                   只保留最近 15 天
├── screenshots/
└── QmlScrcpy.exe
```

**想回到出厂状态**：主窗右上角「重置」按钮会清空 `window.ini` 并重新生成 `config.ini`（重启生效）。


**为什么分成两个 INI**：`QSettings` 写文件时会重写整个 INI，**注释会被转义成 `%23%20...`**。所以让 `config.ini` 只读（我们从不写它），程序自己的窗口状态单独放 `window.ini`。

## config.ini

```ini
# QmlScrcpy 配置，改完重启生效
# 日志级别：debug / info / warning / critical
[log]
level=info
to_file=true
keep_days=15

# 滚轮模式：scroll = 发滚动事件（微信这类），drag = 模拟手指滑动（阅读器、地图）
[input]
wheel_mode=scroll

# 视频采集：长边上限，0 = 设备原生分辨率（更清晰，码率也要跟着涨）
# 有线／兜底
[video]
max_size=0
bit_rate=8000000
max_fps=0

# 无线（串号里带冒号就用这组）
[video_wireless]
bit_rate=6000000
max_fps=0
```

| 项 | 说明 |
|---|---|
| `log/level` | 低于这个级别的**不落盘**（控制台照样输出） |
| `log/to_file` | 关掉就只输出到控制台 |
| `log/keep_days` | 保留最近几天，启动时删更老的 |
| `video/max_size` | 长边上限；0 = 原生分辨率 |
| `video/bit_rate` | 有线码率，原生分辨率建议 8 Mbps |
| `video/max_fps` | 帧率上限，0 = 不限（120Hz 屏能跑 120fps）；**实测对观感影响很小** |
| `video_wireless/bit_rate` | 无线码率，1264×2776 下 6 Mbps 比较舒服 |
| `video_wireless/max_fps` | 无线帧率上限，同上，一般不用改 |
| `input/clipboard_autosync` | 电脑剪贴板一变就自动推到设备，默认 `false` |
| `keys/back` / `keys/home` / `keys/screenshot` / `keys/fullscreen` | 窗口快捷键，默认 `Esc` / `Home` / `Ctrl+Shift+S` / `F11`；留空表示禁用 |
| `ui/boss_key` | 老板键组合，默认 `Ctrl+Alt+B`，必须带修饰键；界面上改过的写 `window.ini` 并优先 |

主窗右上角「画质」按钮能直接改这两项（帧率任意整数、码率可以填小数 Mbps），改完自动重连生效。**有线和无线各一套**：界面里改的写 `window.ini` 的 `[video_wired]` / `[video_wireless]`，优先级高于 `config.ini` 的同名段。

第一次运行自动生成这份带注释的模板；之后我们只读不写。

## 每秒一行链路统计

`[perf]` 那行默认就打印（`QS_PERF=0` 关掉），不依赖日志级别：

```
[perf] 收 46 帧 1340KB/s 关键帧 0 | 推 46 丢 13 | 渲 33（带新帧 30） | 等数据 20.0ms 解码 4.9ms 转换 0.0ms 上屏 0.4ms | 入队到上屏 现在 5.0ms 平均 3.4ms 最大 6.3ms
```

字段含义和怎么用它定位问题，见 [渲染方案](渲染方案.md) 的「每秒一行链路统计」一节。

## 日志格式

```
2026-11-12 11:06:53.405 INFO  [gui]  qsc.input    按下 QPointF(120, 300) 帧尺寸 QSize(1264, 2776) 画布 QSizeF(396, 859)
                        ↑级别  ↑线程  ↑分类        ↑消息
```

- **线程**：`gui` 是主线程，其它是 `t<十六进制 id>`
- **分类**：`qsc.input` / `qsc.session` / `qsc.stream` / `qsc.render`

## 临时改级别

不想动配置文件就用环境变量：

```powershell
$env:QS_LOG_LEVEL="debug"
build\windows-debug\bin\Debug\QmlScrcpy.exe
```

## 为什么是 qDebug 而不是 spdlog

| 维度 | qDebug + message handler | spdlog |
|---|---|---|
| Qt/QML 自己的告警 | **能全拿到**（QML 报错、socket 原因、场景图告警） | 拿不到，得再写 handler 桥接 |
| 依赖 | 无 | 新增一个库 |
| 按天分文件 + 保留天数 | 自己写 ~40 行 | 自带轮转 |

这个项目 80% 的诊断信息来自 Qt 本身，而它们只走 `qInstallMessageHandler`。所以用 qDebug 做后端，外面套一层自己的分类宏；哪天需要上万行/秒的异步日志，只换 `log.cpp`，调用点不动。

## 输入链路的观测点

排查"点了手机没反应"时按顺序看这四行（`QS_LOG_LEVEL=debug`）：

```
qsc.input  按下 QPointF(...) 帧尺寸 ... 画布 ...     ← 事件有没有进来
qsc.input  发出消息 32 字节 0200                     ← 消息有没有拼出来
qsc.input  写控制 socket 32 字节 结果 true           ← 有没有写进 socket
qsc.input  控制 socket 不可用 false                  ← socket 根本没建好
```

哪一行没有，就知道断在哪儿。

## window.ini 里有什么

程序自己的状态全在这，**第一次运行自动生成，手抖删了也会重建**（读不到就用默认值，写的时候重新落盘）。

| 段 | 键 | 含义 |
|---|---|---|
| `[ui]` | `show_console` | 是否显示黑色控制台窗口 |
| | `boss_key` | 老板键，覆盖 `config.ini` 的同名项 |
| `[keys]` | `back` / `home` / `screenshot` / `fullscreen` | 窗口快捷键，空值表示禁用 |
| `[transfer]` | `upload_dir` | 拖文件传到设备的目录 |
| `[video_wired]` | `bitrate` / `max_fps` | 有线档的画面覆盖值 |
| `[video_wireless]` | `bitrate` / `max_fps` | 无线档的画面覆盖值 |
| `[input]` | `wheel_mode` / `drag_pixels` | 滚轮模式与滑动像素 |
| `[device]` | `last_serial` | 上次连接的设备，启动时自动重连 |
| `[control_window]` | `x` `y` `w` `h` | 主窗位置尺寸 |
| `[video_window]` / `[video_window_landscape]` | 同上 | 投屏窗竖屏/横屏的尺寸 |
| `[video_pos]` / `[video_pos_landscape]` | `x` `y` | 投屏窗竖屏/横屏的位置 |

几何类的值用 `-1` 表示"还没记录过"：QML 里判 `width > 0` / `x >= 0` 才套用，否则按默认尺寸走。

**为什么这个文件没有注释**：`QSettings` 每次保存都会按内存里的键表重写整个文件，注释一律丢（`#` 还会被当成键名转义成 `%23`）。注释只放在 `config.ini` 里——那个文件程序从不写。
