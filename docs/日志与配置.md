# 日志与配置

## 文件位置

配置文件统一在 exe 下的 `config/` 目录，日志和截图各自独立；绿色软件，拷走整目录就能用：

```
bin/Debug/
├── config/
│   ├── config.ini      用户手改：日志级别、采集参数、滚轮默认值
│   └── window.ini      程序自己写：窗口位置尺寸、上次设备、命令行开关
├── Log/
│   ├── LOG_2026_11_12.log    今天的日志，按天一个文件
│   ├── LOG_2026_11_11.log
│   └── ...                   只保留最近 15 天
├── screenshots/
└── QmlScrcpy.exe
```

**想回到出厂状态**：主窗右上角「重置」按钮会清空 `window.ini` 并重新生成 `config.ini`（重启生效）。


**为什么分成两个 INI**：`QSettings` 写文件时会重写整个 INI，**注释会被转义成 `%23%20...`**。所以让 `config.ini` 只读（我们从不写它），程序自己的窗口状态单独放 `window.ini`。

## config.ini

```ini
# QmlScrcpy 配置，改完重启生效
# 日志级别：debug / info / warning / critical
[log]
level=info
to_file=true
keep_days=15

# 滚轮模式：scroll = 发滚动事件（微信这类），drag = 模拟手指滑动（阅读器、地图）
[input]
wheel_mode=scroll

# 视频采集：长边上限，0 = 设备原生分辨率（更清晰，码率也要跟着涨）
# 有线／兜底
[video]
max_size=0
bit_rate=8000000
max_fps=0

# 无线（串号里带冒号就用这组）
[video_wireless]
bit_rate=6000000
max_fps=0
```

| 项 | 说明 |
|---|---|
| `log/level` | 低于这个级别的**不落盘**（控制台照样输出） |
| `log/to_file` | 关掉就只输出到控制台 |
| `log/keep_days` | 保留最近几天，启动时删更老的 |
| `video/max_size` | 长边上限；0 = 原生分辨率 |
| `video/bit_rate` | 有线码率，原生分辨率建议 8 Mbps |
| `video/max_fps` | 帧率上限，0 = 不限（120Hz 屏能跑 120fps）；**实测对观感影响很小** |
| `video_wireless/bit_rate` | 无线码率，1264×2776 下 6 Mbps 比较舒服 |
| `video_wireless/max_fps` | 无线帧率上限，同上，一般不用改 |
| `input/clipboard_autosync` | 电脑剪贴板一变就自动推到设备，默认 `false` |
| `keys/back` / `keys/home` / `keys/screenshot` / `keys/fullscreen` | 窗口快捷键，默认 `Esc` / `Home` / `Ctrl+Shift+S` / `F11`；留空表示禁用 |
| `ui/boss_key` | 老板键组合，默认 `Ctrl+Alt+B`，必须带修饰键；界面上改过的写 `window.ini` 并优先 |

主窗右上角「画质」按钮能直接改这两项（帧率任意整数；码率是六档预设：流畅 4 / 标准 8 / 清晰 12 / 高清 16 / 超清 20 / 至臻 24 Mbps），改完自动重连生效。**有线和无线各一套**：界面里改的写 `window.ini` 的 `[video_wired]` / `[video_wireless]`，优先级高于 `config.ini` 的同名段。

第一次运行自动生成这份带注释的模板；之后我们只读不写。

## 每秒四行统计（默认开）

连上设备后每秒打四行，info 级别就有，不需要改配置：

```
[perf] 1s 到达 113 帧，上屏 113 帧，丢 0（0.0%），实际 1180 KB/s（9.4 Mbps）
[perf]     上屏延迟 <1.5ms 49% / 1.5~2.5ms 40% / 2.5~3.5ms 10% / >3.5ms 1%，最大 4.0 ms
[perf]     到达间隔 <8.5ms 57% / 8.5~17ms 43% / 17~34ms 1% / >34ms 0%
[perf]     上屏间隔 <8.5ms 55% / 8.5~17ms 44% / 17~34ms 1% / >34ms 0%
```

| 行 | 字段 | 含义 |
|---|---|---|
| 第一行 | 到达 | 解码后真正交到画布的帧（`Present` 次数） |
| | 上屏 | 真正提交给系统的帧（`frameSwapped`，只算本轮取了新帧的） |
| | 丢 / 丢帧率 | 还没画就被新帧顶掉的帧 / 占比；`丢 0` 只说明每帧都画了，不代表顺滑 |
| | 实际 / KB/s / Mbps | 这一秒从链路真正收到的视频字节数；和配置里的码率上限对比，就能看出编码器有没有超发 |
| 第二行 | **上屏延迟** | **一帧从到达画布到真正上屏的时间**（不是帧间隔、不是网络延迟） |
| 第三行 | **到达间隔** | 相邻两帧到达的间隔，换算过来就是源帧率：`<8.5ms`≈120fps 以上、`8.5~17ms`≈60fps、`17~34ms`≈30fps、`>34ms` 更低 |
| 第四行 | **上屏间隔** | 相邻两次真正上屏的间距，和到达间隔并排看：两者接近说明客户端没额外引入抖动 |

`丢 0` 只说明每帧都画了，不代表顺滑。卡往往来自帧到达不匀（抖动），更多见 [渲染延迟](渲染延迟.md) 第十四节。

两个分布都用分档而不是平均：平均值会把 0.3ms 和 6ms 的帧糊成一个"看起来还行"的数，这次排查已经吃过两次亏。

桶边界是按实测分布定的：上屏延迟中位在 1.7ms 左右，所以切在 1.5 / 2.5 / 3.5；到达间隔按帧率档位切，比按绝对毫秒更直观。

> 窗口还没显示时那一秒全是"丢"，这种秒不打印，避免启动噪音。

## 逐帧追踪（`QS_TRACE_FRAMES=1` 才开）

需要看每一帧的九段耗时，设环境变量再启动：

```powershell
$env:QS_TRACE_FRAMES="1"; .\QmlScrcpy.exe
```

启动日志里会有一行 `[perf] 逐帧追踪 开` 确认开关状态。每个渲染轮次打一行：

```
  帧 166 上屏：到达间隔 9.22，GUI 排队 0.074，GUI 到渲染线程 0.109，唤醒 0.109，预处理 0.008，取帧 0.681，画一帧 0.821，交换阻塞 0.337，从到达到上屏 2.112 ms
  帧 167 丢掉：到达间隔 4.05 ms，存活 3.2 ms
[perf]     上屏间隔 <8.5ms 55% / 8.5~17ms 44% / 17~34ms 1% / >34ms 0%
```

| 字段 | 量的代码 |
|---|---|
| `帧 N` | 每帧一个自增序号，同一行的数都属于这一帧 |
| `到达间隔` | 这一帧到达 − 上一帧到达 |
| `GUI 排队` | 投递 → lambda 开始执行 |
| `唤醒` / `预处理` | `update()` 完 → `beforeSynchronizing` → `synchronize` |
| `取帧` / `画一帧` | `synchronize()` / `render()` 全程 |
| `交换阻塞` | `render()` 结束 → `frameSwapped` |
| `从到达到上屏` | 到达 → 交换完成 |

**默认不开的原因**：逐帧追踪每帧要建一个 `FrameTrace` 并打一行日志，开销在分配和 I/O 上；不开时只有四个计数和两个时间戳，可以忽略。

## 临时改级别

不想动配置文件就用环境变量：

```powershell
$env:QS_LOG_LEVEL="debug"
build\windows-debug\bin\Debug\QmlScrcpy.exe
```

## 为什么是 qDebug 而不是 spdlog

| 维度 | qDebug + message handler | spdlog |
|---|---|---|
| Qt/QML 自己的告警 | **能全拿到**（QML 报错、socket 原因、场景图告警） | 拿不到，得再写 handler 桥接 |
| 依赖 | 无 | 新增一个库 |
| 按天分文件 + 保留天数 | 自己写 ~40 行 | 自带轮转 |

这个项目 80% 的诊断信息来自 Qt 本身，而它们只走 `qInstallMessageHandler`。所以用 qDebug 做后端，外面套一层自己的分类宏；哪天需要上万行/秒的异步日志，只换 `log.cpp`，调用点不动。

## 输入链路的观测点

排查"点了手机没反应"时按顺序看这四行（`QS_LOG_LEVEL=debug`）：

```
qsc.input  按下 QPointF(...) 帧尺寸 ... 画布 ...     ← 事件有没有进来
qsc.input  发出消息 32 字节 0200                     ← 消息有没有拼出来
qsc.input  写控制 socket 32 字节 结果 true           ← 有没有写进 socket
qsc.input  控制 socket 不可用 false                  ← socket 根本没建好
```

哪一行没有，就知道断在哪儿。

## window.ini 里有什么

程序自己的状态全在这，**第一次运行自动生成，手抖删了也会重建**（读不到就用默认值，写的时候重新落盘）。

| 段 | 键 | 含义 |
|---|---|---|
| `[ui]` | `show_console` | 是否显示黑色控制台窗口 |
| | `boss_key` | 老板键，覆盖 `config.ini` 的同名项 |
| `[keys]` | `back` / `home` / `screenshot` / `fullscreen` | 窗口快捷键，空值表示禁用 |
| `[transfer]` | `upload_dir` | 拖文件传到设备的目录 |
| `[video_wired]` | `bit_rate` / `max_fps` | 有线档的画面覆盖值 |
| `[video_wireless]` | `bit_rate` / `max_fps` | 无线档的画面覆盖值 |
| `[input]` | `wheel_mode` / `drag_pixels` | 滚轮模式与滑动像素 |
| `[input]` | `drag_scale` / `pinch_modifier` | 左键拖拽倍率（1.0~3.0）、捏合修饰键（ctrl / alt / shift / ctrl_alt / none） |
| `[device]` | `last_serial` | 上次连接的设备，启动时自动重连 |
| `[control_window]` | `x` `y` `w` `h` | 主窗位置尺寸 |
| `[video_window]` / `[video_window_landscape]` | 同上 | 投屏窗竖屏/横屏的尺寸 |
| `[video_pos]` / `[video_pos_landscape]` | `x` `y` | 投屏窗竖屏/横屏的位置 |

几何类的值用 `-1` 表示"还没记录过"：QML 里判 `width > 0` / `x >= 0` 才套用，否则按默认尺寸走。

**为什么这个文件没有注释**：`QSettings` 每次保存都会按内存里的键表重写整个文件，注释一律丢（`#` 还会被当成键名转义成 `%23`）。注释只放在 `config.ini` 里——那个文件程序从不写。
