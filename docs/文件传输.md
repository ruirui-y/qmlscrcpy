# 文件传输

把电脑上的文件拖进投屏窗，松手就推到手机的 `/sdcard/Download/QmlScrcpy/`（可在设置里改），状态栏实时显示进度。

## 1. 怎么用

```
① 资源管理器里选中文件（可以多选）
② 拖到投屏窗的画面上，边框变蓝并提示"松手传到手机 …"
③ 松手 → 状态栏显示 "传 文件名：45%"
④ 传完显示 "N 个文件已传到手机 …"
```

手机上用「文件管理」进 Download/QmlScrcpy 就能看到。

## 2. 为什么用 adb push 而不是 protocol

scrcpy 协议里没有文件传输——它的定位是投屏和输入，传文件一直是外部工具的事（QtScrcpy 也是自己调 adb）。所以这里直接 `adb push`：

```
adb -s <序列号> push <本地路径> /sdcard/Download/QmlScrcpy/
```

好处：不需要动服务端、不占视频带宽、进度由 adb 自己报。

## 3. 进度怎么来的

`adb push` 把进度写在 **stdout** 里，形如：

```
/sdcard/Download/QmlScrcpy/big.bin: [ 45%] 1024/2048
```

所以不能像别的 adb 调用那样"跑完拿输出"，必须**边跑边读**：

```cpp
while (process.state() != QProcess::NotRunning)
{
    if (process.waitForReadyRead(200))
    {
        consume(process.readAllStandardOutput());
    }
}
```

`consume()` 按行切、用正则 `\[\s*(\d+)%\]` 抓百分比，抓到就回调。文件很小时 adb 只打最后一行 `1 file pushed`，没有百分比行——那就只在结束时补一个 100。

## 4. 为什么必须放工作线程

`adb push` 是阻塞的，几 GB 的文件能跑几分钟。放 GUI 线程就是"窗口未响应"。

```cpp
QThread *worker = QThread::create([this, serial, paths, upload_dir]() { /* 逐个 push */ });
```

进度回调里不能再直接改状态栏（工作线程），要投递回主线程：

```cpp
QMetaObject::invokeMethod(this, [this, name, percent]() {
    SetStatus(QStringLiteral("传 %1：%2%").arg(name).arg(percent));
}, Qt::QueuedConnection);
```

## 5. 中文文件名：adb 的坑

直接 `adb push` 中文名文件会失败：

```
adb: error: failed to copy 'C:\...\支持打字和缩放.mp4'
  to '/sdcard/Download/QmlScrcpy/.': remote couldn't create file: Is a directory
```

注意远端路径变成了 `.../QmlScrcpy/.`——**文件名被吞成空串**。原因是 adb.exe 在 Windows 上按 ANSI 解释命令行参数，非 ASCII 文件名传不过去。

绕法两步：

```
① adb push <本地中文名文件> /sdcard/Download/QmlScrcpy/qmlscrcpy_7.mp4
② adb shell mv /sdcard/Download/QmlScrcpy/qmlscrcpy_7.mp4 \
     "/sdcard/Download/QmlScrcpy/$(echo <base64> | base64 -d)"
```

第二条里的 base64 是纯 ASCII，不受代码页影响；设备上的 shell 负责解码成 UTF-8 文件名。

**还踩了一个**：最初第二条写成 `mv <temp> "$(echo ... | base64 -d)"`——解码出来只有文件名、没有目录前缀，`mv` 按相对路径落到只读的 `/`，报 `Read-only file system`。必须把目录拼回去。

## 6. 在手机上打开这个目录

传完文件不用去翻文件管理器：工具栏点「目录」，手机上手机会自动弹出文件管理器。

实现（`DeviceController::OpenUploadDir()`）：

```
① adb shell mkdir -p /sdcard/Download/QmlScrcpy       目录得先存在
② adb shell am start -n com.android.documentsui/.files.FilesActivity \
       -d "content://com.android.externalstorage.documents/document/primary%3ADownload%2FQmlScrcpy"
③ 上面失败就退回：am start -a android.intent.action.VIEW_DOWNLOADS
```

**已知不完美**：部分机型（比如实测的 realme）不会停在子目录，只打开「下载」根目录——`QmlScrcpy` 文件夹就在第一项，点一下就到。相比之下用 `content://` 走 `VIEW` 会弹出"用哪个应用打开"的选择框，更烦。

路径里的 `%2F` 是 `content://` 文档 URI 要求的：`primary:Download/QmlScrcpy` 里的 `/` 要转义。

## 7. 目标目录可配置

默认 `/sdcard/Download/QmlScrcpy`，在设置窗「文件上传目录」里改，改完立即生效并记进 `window.ini`（覆盖 `config.ini` 的 `[transfer] upload_dir`）。

目录不存在时程序先 `adb shell mkdir -p` 建出来再推。

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 没连设备 | 状态栏"还没连接设备"，不启动线程 |
| 拖进来的是文件夹 | 过滤，提示"拖进来的都是文件夹，暂不支持"（目录要 `push -r`） |
| 多个文件 | 逐个 push，任何一个失败就停并报文件名 + adb 的错误原文 |
| 目标目录不存在 | 先 `mkdir -p` |
| 文件名带空格 | 走 QProcess 参数数组，不经 shell，不会被拆开 |
| 文件名含中文 | ASCII 临时名 + base64 改名，见上一节 |
| 上传目录填错 | 必须是 `/` 开头的绝对路径，否则拒绝并提示 |

## 9. 已知限制

- 只支持**电脑 → 手机**，反向还没做
- 不支持文件夹
- 大文件传输期间没有取消按钮

## 10. 验证

adb 层单独验过：

```
$ adb -s e77121ed push test.bin /sdcard/Download/QmlScrcpy/
test.bin: 1 file pushed, 0 skipped. 40.1 MB/s (2097152 bytes in 0.050s)

$ adb -s e77121ed shell ls -l /sdcard/Download/QmlScrcpy/
-rw-rw---- 1 u0_a298 media_rw 10547775 ... 支持打字和缩放.mp4
```

第二条是中文名文件走"临时名 + base64 改名"之后的最终结果。

界面上的拖放需要人工验（自动化模拟拖拽不可靠），日志里有 `[drop]` 前缀可以对照：

```
[drop] 收到 1 个 url
[drop] url "file:///C:/.../支持打字和缩放.mp4" 本地路径 "C:/.../支持打字和缩放.mp4" 是文件 true
[drop] 开始 push "C:/.../支持打字和缩放.mp4" -> "/sdcard/Download/QmlScrcpy"
[drop] push 完成 支持打字和缩放.mp4
```
