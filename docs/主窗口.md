# 主窗口（控制窗）

设备串号输入、连接/断开、状态显示都在这里。画面在投屏窗，常用操作在工具栏。

## 布局

```
┌──────────────────────────────────────────────────────────┐
│ QmlScrcpy                                       [ 设置 ]  │
├──────────────────────────────────────────────────────────┤
│ [e77121ed          ] [▾] [刷新] [连接] [断开]              │  只有一行
├──────────────────────────────────────────────────────────┤
│ ● 已连接 RMX5010 1264x2776                                │
└──────────────────────────────────────────────────────────┘
```

**为什么只留一个「设置」入口**：画质、老板键、命令行、恢复默认、快捷键映射加起来有 5 组控件，全塞进 600×250 会挤成一排小方块。所以主窗只负责"连接"，其余都在设置窗里。

### 设置窗（520×560，独立小窗）

```
┌─ 设置 ─────────────────────────────────────── ✕ ─┐
│ 画质（改完自动重连）                                │
│  帧率 [60]  码率 [清晰（12 Mbps）▾] [应用并重连]    │
│ ───────────────────────────────────────────────── │
│ 快捷键（留空表示禁用；老板键是全局热键）              │
│  返回     [Esc           ]                        │
│  回桌面   [Home          ]                        │
│  截图     [Ctrl+Shift+S  ]                        │
│  全屏     [F11           ]                        │
│  老板键   [Ctrl+Alt+B    ]        [保存快捷键]      │
│ ───────────────────────────────────────────────── │
│ 文件上传目录（拖文件进投屏窗时用）                    │
│  [/sdcard/Download/QmlScrcpy      ]  [保存目录]     │
│ ───────────────────────────────────────────────── │
│ 其他                                               │
│  [命令行：关]  [恢复默认配置]                       │
└───────────────────────────────────────────────────┘
```

用**独立窗口**而不是 `Popup`：QML 的 Popup 画在父母口内部，主窗只有 250 高，塞不下 500 多高的表单；之前 ToolTip 用 `popupType: Popup.Window` 还崩过（栈溢出），所以直接开一扇真窗口。

设置窗是 **`modality: Qt.NonModal`**。一开始用的 `ApplicationModal`，结果开着设置窗时**往投屏窗拖文件没反应**——模态窗口会挡掉其它窗口的拖放事件。设置只是一张表单，没必要阻塞；关闭靠 ✕ 或 `Esc`。

`[▾]` 打开设备菜单：

```
USB   e77121ed
无线  192.168.31.114:5555
──────────────────────────
用 USB 设备开无线调试          ← 蓝色，点一下切无线
```

**为什么把"切无线"放进菜单**：主窗只留一行操作，日常用不到它就藏起来；但"一开始没有无线怎么切"这个问题必须有入口——菜单最后一项就是它，鼠标点两下就到，不用挤一行按钮。

- 圆角卡片（`radius 10` + 细边框）把串号区和状态区从背景里分出来
- 状态点：连上了是绿色 `#3ecf8e`，没连是灰色 `#5a6272`
- 「连接」按钮是主色（蓝），其余是次要色

## 为什么所有控件都自绘背景

第一版直接用 `Button` / `TextField` 的默认样式，结果：

- 深色窗口上出现一排**白底方块**（默认样式是浅色的）
- 把窗口拖到另一块**不同缩放比例的屏幕**上，按钮会变成半截白条——因为默认样式按 DPI 重算背景，而尺寸约束没跟着更新

现在按钮是 `ActionButton`（`Rectangle` + `Text` + `MouseArea`），输入框只覆盖 `background`，颜色全部写死：

```qml
color: area.containsMouse ? (primary ? "#5aa9ff" : "#2e343e")
                          : (primary ? "#3f8fdd" : "#242932")
```

这样换屏幕、换 DPI 都不会跑版。

## 窗口位置会记住

控制窗自己也记位置和尺寸，写在 `window.ini` 的 `[control_window]`：

```ini
[control_window]
x=929
y=333
w=560
h=340
```

启动时读回来；拖动/缩放后防抖 400ms 写一次；第一次运行没有记录时，把 Qt 给的默认位置立刻存下来，保证下次还在那儿。

**最小尺寸 560×300** 是算出来的：串号输入框最少 130 + 三个按钮 72×3 + 间距，小于这个宽度内容就会被裁掉。换屏时 DPI 变了 Qt 会重算窗口尺寸，`onScreenChanged` 里再兜一次，避免出现"按钮只剩半截"。

## 在线设备列表（选一个就连上）

`adb devices` 能看到的设备 + `adb mdns services` 广播的无线设备，合并成一张列表，下拉框里带类型前缀：

```
USB   e77121ed
无线  192.168.31.114:5555
无线  192.168.31.120:37015      ← mdns 发现的
```

**选中只把地址填进输入框**，连不连由用户点「连接」决定——避免"点一下列表就偷偷连上"这种不可控行为。输入框也可以手填 `IP:端口`。

自动连接只在"上次那台出现在扫描结果里"时才发生；扫不到就不连，不白等一次失败。

## 启动只亮主窗

程序启动时只显示控制窗，投屏窗保持隐藏（`visible: false`），连上会话之后才出现：

```qml
Connections {
    target: deviceController
    function onConnectedChanged() {
        videoWindow.visible = deviceController.connected
    }
}
```

断开连接时自动收起。

**关掉投屏窗会连带断开连接**：✕ 和 `Alt+F4` 都走 `deviceController.Disconnect()`。第一版只把窗口 `visible = false`，结果主窗还显示"已连接"，而「连接」按钮对已连接的会话不会再触发 `connectedChanged`，投屏窗就再也叫不回来了，用户必须先点「断开」再点「连接」。

## 弹窗必须能塞进窗口

QML 的 `Popup`（`popupType` 默认是 `Popup.Item`）**画在窗口内部**，不是独立窗口，所以面板高度必须小于窗口可用高度，否则底部的「应用并重连」会被裁掉。

一开始的做法是把控制窗加高到 350，观感太丑；改成**把面板压紧**，250 高的窗口也放得下：

| 项 | 原值 | 现值 |
|---|---|---|
| 面板 padding | 12 | 8 |
| 行间距 | 8 | 6 |
| 输入框高度 | 30 | 26 |
| 按钮高度 | 30 | 26 |
| 提示文字字号 | 10 | 9 |
| 弹窗 y（相对头部行） | 56 | 18 |

压完总高约 164px，`y=18 + 头部行 16 = 34`，底部到 198，250 高的窗口留足余量。

**注意**：改了窗口默认高度后可能看着没变，因为 `window.ini` 里记着旧高度，启动时是 `Math.max(minimumHeight, saved.height)`。主窗「重置」或删掉 `[control_window]` 段才会用新默认值。

## 重置配置## 重置配置

右上角「重置」按钮打开确认框：

```
┌────────────────────────────┐
│ 恢复默认配置？               │
│ 会清空窗口位置尺寸、上次设备、 │
│ 画质参数、命令行开关，并重新   │
│ 生成默认的 config.ini。当前   │
│ 连接不会断开，重启程序后生效。 │
│        [取消]   [恢复]       │
└────────────────────────────┘
```

「恢复」做两件事：

```cpp
window_store.clear();  window_store.sync();   // window.ini 清空
QFile::remove(ConfigPath());                   // config.ini 删掉，下次启动重新生成
EnsureDefaultConfig();                        // 立刻补一份带注释的模板回来
```

不重启的话当前会话还用着旧值（滚轮模式、画质、窗口尺寸都不会突变），状态栏会提示"已恢复默认配置，重启程序后生效"。

## 画质面板

右上角「画质 8M/60」按钮打开一个面板：

```
┌──────────────────────────┐
│ 帧率上限（0 = 不限）       │
│ [60                  ]   │
│ 码率下拉（6 档预设）       │
│ [8.0                 ]   │
│ 改完会自动断开重连（1~2 秒）│
│ [   应用并重连         ]  │
└──────────────────────────┘
```

为什么必须重连：`bit_rate` / `max_fps` 是 scrcpy-server 的**启动参数**，server 起来后固定在编码器里；控制消息里没有"改码率"这一条。所以「应用」= 写配置 + 断开 + 用新参数重连。

**有线和无线各一套**，面板只改当前连接方式那一套：

```ini
# config.ini（默认值）
[video]                 # 有线
bit_rate=8000000
max_fps=0

# 无线：串号里带冒号就用这组
[video_wireless]
bit_rate=6000000
max_fps=0

# window.ini（界面里调过的，优先级更高）
[video_wireless]
bit_rate=5000000
```

读取顺序：`window.ini` 的 `[video_<档位>]` → `config.ini` 的 `[video_<档位>]` → `config.ini` 的 `[video]` → 内置 8Mbps。

实测结论（2026-11，逐帧统计）：**帧率参数是"上限"，能不能用上取决于应用自己**——应用锁 60Hz 时填 120 也只有 58 帧，抖音切到 120Hz 后能到 97 帧。**码率同时约束帧率**：2M 只出 72 帧、6M 94 帧、12M 114 帧（1264×2776 原生分辨率）。

所以码率改成下拉预设，直接对应观感档位：

| 档位 | 码率 | 单帧约（60fps） | 适用 |
|---|---|---|---|
| 流畅 | 4 Mbps | 8 KB | 2.4G 无线、弱网 |
| 标准 | 8 Mbps | 17 KB | 默认，无线够用 |
| 清晰 | 12 Mbps | 25 KB | 5G 无线、常看视频 |
| 高清 | 16 Mbps | 33 KB | 有线推荐 |
| 超清 | 20 Mbps | 42 KB | 有线、追求细节 |
| 至臻 | 24 Mbps | 50 KB | 有线、视频/游戏 |

配置文件里写非预设值（比如 6M）时，下拉第一项会显示「当前（6 Mbps）」，选过预设之后就被覆盖。

写入位置是 `window.ini` 的 `[video]`，优先级高于 `config.ini`。

## 主窗只负责"连接"

除了连接状态，其它状态都不在主窗：帧率、分辨率、悬停提示全在**投屏窗标题栏**。主窗就三行——标题、一行操作、一行连接状态。

## 字号

深色小窗口里 12px 太细，标题和工具栏文字都提到 13~14px 并加粗，投影屏上也看得清。

## 标题栏显示设备

投屏窗标题绑的是当前设备串号：

```qml
title: deviceController.deviceName.length > 0
       ? "QmlScrcpy — " + deviceController.deviceName : qsTr("QmlScrcpy — 投屏")
```

- 有线连接 → 序列号，例如 `QmlScrcpy — e77121ed`
- 无线连接 → `IP:端口`，例如 `QmlScrcpy — 192.168.31.115:5555`
- 断开后回到默认标题

`deviceName` 是 `DeviceController` 的属性，`Connect()` 时设成传进来的串号，`TearDown()` 时清空。

## 状态文字来自哪

`deviceController.status`，由控制器在每个阶段改写：

| 阶段 | 文字 |
|---|---|
| 刷新 | `找到 1 台设备` / `没找到在线设备` |
| 连接中 | `正在连接 <串号> …` |
| 连上 | `已连接 <型号> <宽>x<高>` |
| 失败 | `连接失败：<原因>` |
| 工具栏动作 | `滚轮模式：滑动` / `滑动像素：29` / `已息屏` / `截图已保存并复制：shot_xxx.png` |

## WiFi 健康度（只有无线连接时显示）

主窗底部状态行最右边会多一块：

```
● WiFi 5G  -49 dBm  1297 Mbps 重传 13.1%
```

鼠标悬停弹出详情气泡（自绘深色，和整套主题一致）：SSID、BSSID、WiFi 标准、频段、Tx/Rx 速率、累计重传/发送、累计丢包。

气泡贴着芯片正上方弹出、右对齐，并用 `Math.max/min` 夹在窗口内——早期版本固定在窗口右下角，气泡会超出边界被裁掉。

### 数据怎么来的

每 3 秒跑一次：

```bash
adb shell cmd wifi status
```

从这一大段里挑几个字段：`RSSI`、`Link speed`、`Frequency`、`Wi-Fi standard`、`retriedTxPackets`、`lostTxPackets`。

**重传率按增量算**：拿这一轮和上一轮的 `retriedTxPackets`、`successfulTxPackets` 相减，再算比例。用累计值会越跑越平滑，看不出当下好坏。

### 颜色四档

| 等级 | 条件 | 颜色 |
|---|---|---|
| 好 | RSSI ≥ -60 且重传 < 5% | 绿 |
| 一般 | RSSI -60~-70 或重传 5~10% | 黄 |
| 差 | RSSI -70~-78 或重传 10~20% | 橙 |
| 很差 | RSSI < -78 或重传 > 20% 或出现丢包 | 红 |

信号和重传率谁差取谁——有时候信号满格但空口拥挤，重传率会先红。

### 为什么用重传率而不是只看 RSSI

实测例子：RSSI -46 dBm（很好），但重传 13.1%，说明空口有干扰或在排队。**RSSI 只说明信号强度，不能说明链路质量**。

### 有线连接时

不显示这一块，代码里 `WifiStatus::Stop()` 会把定时器和数据一起清掉。
